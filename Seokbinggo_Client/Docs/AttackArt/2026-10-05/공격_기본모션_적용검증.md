- attack_file.zip, Fan_attack.zip 원본 13개를 복사했다. 기본 플레이어 수정본은 기존 player_frostclaw.aseprite 경로와 GUID를 유지해 교체했다.
- 도깨비 방망이, 각궁, 도관 노, 성에 각궁, 짚 투석기, 합죽선, 철선, 설풍선, 서리 부채, 한파 부채의 전용 플레이어 공격 모션 59프레임을 연결했다.
- Fan_attack→hapjukseon, fan_cold_attack→cold_wave_fan은 사용자 확인에 따라 확정했다.

- 무기 모션은 원본 순서로 1회 재생한 후 이동 상태로 복귀한다. 원본 재생 시간이 공격 간격보다 길면 간격 안에 전체 프레임이 들어가도록 압축한다. 공격 속도·피해량·탄약 수치는 보존한다.
- 짚 투석기는 돌, 다른 활 계열은 화살 원본을 사용한다. 그림상 발사 프레임은 각궁·성에 각궁 3, 도관 노 6, 짚 투석기 4(0부터)로 설정했다. 후속 사용자 요청으로 활의 즉시 사선 타격을 제거했으며, 투사체가 이동 중 몬스터 콜라이더에 충돌할 때만 피해를 준다.
- 원본 화살의 왼쪽 방향에 맞춰 비행 방향으로 회전하고, 피벗 대신 그림 중심을 비행 경로에 맞췄다. 사망·삼킴 시 연출은 중단·제거한다.
- ApplyPlayerWeaponArt는 플레이어와 이번 공격·투사체 카탈로그 항목만 갱신한다. 다른 캐릭터, 로프, 월드 아트 및 기존 사용자 작업은 보존한다.

## 검증

- Unity MCP 실제 응답으로 10개 무기별 원본 경로, 프레임 수, null 프레임 0, PPU 16, Point 필터를 확인했다. 두 투사체도 동일 설정을 확인했다.
- 플레이어 프레임 수와 로프 원본 GUID d16bcf964c9e6104e9ca1e81501f496e를 확인했다.
- 원본 복사 이력·SHA256: 적용_원본대조.json. Unity 실물 카탈로그 조회: Unity_연결_검증.json.
- CPU C# 순차 컴파일: Assembly-CSharp 오류 0 / 경고 3, Assembly-CSharp-Editor 오류 0 / 경고 38.
- Unity 콘솔 오류 0. Unity는 플레이 모드가 아니었으며 게임 실행·런타임 테스트·GPU 검증을 수행하지 않았다.
- 저장 데이터·아이템 ID·레시피·전투 수치는 변경하지 않았다. 런타임 생성 시 기존 카탈로그에서 프레임을 읽는다.

## 직접 플레이 확인

1. 기본 대기·걷기·점프·사망이 새 그림이며 로프 W/S 모션이 유지되는지 확인한다. 별도 낙하·착지 원본은 이번에도 없다.
2. 방망이와 활 4종을 각각 장착하고 좌클릭한다. 좌우에서 해당 무기로 공격하고, 몸체가 중복 표시되거나 발 위치가 흔들리지 않는지 확인한다.
3. 활은 돌 탄약이 있을 때만 공격된다. 각궁·성에 각궁·도관 노는 화살, 짚 투석기는 돌 연출이 발사 방향으로 이동하는지 확인한다.
4. 도관 노를 연속 공격해 모션 마지막 프레임이 반복 입력에서 잘리는지 확인한다. 발사 전·명중 전에는 피해가 없어야 하며, 그림과 투사체 출현 시점·명중 피드백은 런타임 미검증이다.
5. 부채 5종은 F로 능력을 사용한다. 성공 시 해당 부채 모션이 재생되고 쿨타임 중에는 다시 재생되지 않는지 확인한다.
6. 공격 후 걷기·점프·로프 등반으로 복귀하고, 사망·타이틀 이동 후 연출 오브젝트가 남지 않는지 확인한다.

## 후속 아트

신기전 손대(singijeon_sondae), 한파 신기전(cold_wave_singijeon), 얼음뿌리 채찍선(ice_root_whipfan)은 이번 ZIP에서 전용 공격 원본을 확인하지 못했다. 다른 무기의 몸체 공격 그림을 대체 연결하지 않았으며 기존 기본 공격 모션을 유지한다.

## 후속: 실제 투사체 타격

- 활 6종의 기본 공격은 MeleeArcAttack.Strike를 호출하지 않는다. 탄약 소비와 쿨타임은 입력 승인 시 한 번, 피해는 발사 지연 후 충돌 시 한 번 발생한다.
- 발사 시 피해량·넉백·최대 대상 수·기존 냉기 설정·공격자·피해 보정 및 넉백 알림을 보관한다. 비행 중 장비를 교체해도 발사한 탄의 수치가 바뀌지 않는다.
- 14타일/초, 충돌 반경 0.1타일. 이동 구간을 CircleCast로 검사하고 가까운 충돌부터 처리한다. useTriggers=true로 몬스터 트리거도 검사하며, 같은 Health의 여러 콜라이더는 한 번만 처리한다.
- 공격자와 죽은 대상은 제외한다. 프로필 MaxTargets에 도달하면 소멸한다. 신기전 손대 3체·한파 신기전 5체 설정을 실제 SO에서 확인했다.
- 전경 TilemapCollider2D·CompositeCollider2D의 비트리거 지형 충돌에서 소멸한다. 아이템 드롭 등 관계없는 콜라이더에는 피해를 주거나 멈추지 않는다. 근접·부채 판정은 보존한다.
- 사거리 종료, 사망·삼킴 시 소멸하며, 타이틀 이동 시 씬 오브젝트와 함께 정리된다. 투사체 자체는 저장하지 않는다.
- 변경 파일은 MainGamePlayerController와 MeleeArcAttack이다. 기존 A/C 플레이어 입력과 공통 전투 파일에 변경이 있으므로 팀 병합 시 이 두 파일을 확인한다.
- CPU 순차 컴파일 오류 0(런타임 경고 3 / 에디터 경고 38), git diff --check 오류 없음. MCP 콘솔 조회 오류 0. 사용자가 Unity에서 플레이 중인 상태였으므로 에이전트가 게임 상태를 변경하거나 플레이·물리 테스트를 수행하지 않았다.

### 추가 플레이 확인

1. 몬스터와 거리를 두고 발사한다. 버튼을 누른 순간이 아니라 화살/돌이 닿을 때 체력이 감소해야 한다.
2. 몬스터가 비행 경로를 벗어나면 빗나가고, 빈 공간으로 쏜 탄이 가까운 다른 대상을 찾아 명중해서는 안 된다.
3. 바로 옆의 몬스터도 맞고, 같은 몬스터의 여러 콜라이더에 닿아도 피해와 넉백은 한 번만 발생해야 한다.
4. 일렬 대상에 일반 활은 1체, 신기전 손대는 최대 3체, 한파 신기전은 최대 5체까지만 명중해야 한다.
5. 벽 뒤 대상은 맞지 않아야 한다. 벽·사거리 끝·사망·타이틀 전환에서 탄이 남지 않아야 한다.
6. 발사 직후 무기를 교체해도 기존 탄의 피해량·관통 수는 발사한 무기 기준이어야 한다.
7. 탄약은 발사 입력 한 번에 돌 1개만 소비하고, 관통으로 여러 대상을 맞힐 때 추가 소비하지 않아야 한다. 방망이·발톱·부채 F도 기존대로 확인한다.

## 후속: 공격 방향 우선

- 기본 공격과 부채 F가 승인되면 해당 공격 시작 시점의 좌우 방향으로 몸체를 고정한다. 모션 재생 중 매 프레임 들어오는 이동 방향은 스프라이트 방향을 덮어쓰지 않는다.
- 플레이어의 horizontalFacing·이동 입력·속도는 공격 때문에 변경하지 않는다. 공격 모션 종료 후 다음 이동 프레임에서 실제 이동 방향을 다시 바라본다. 다음 공격이 승인되면 새 공격 방향으로 갱신한다.
- 전용 원본이 없는 무기의 기본 공격 모션에도 적용한다. 사망·초기화·다른 액션으로 전환되면 방향 고정을 해제한다. 순수 위/아래 조준은 현재 좌우 스프라이트 방향을 유지한다.
- 런타임·에디터 순차 CPU 컴파일 오류 0(경고 3 / 38), Unity 콘솔 조회 오류 0, diff 공백 오류 없음. 실제 플레이는 미검증.
- 플레이 확인: D로 오른쪽 이동하며 왼쪽에 공격하면 몸체는 모션 동안 왼쪽, 이동은 오른쪽이어야 한다. 반대 조합도 확인한다. 모션 종료 후 이동 방향으로 복귀하고, 연속 공격·부채 F·점프 중 공격에서도 유지되는지 확인한다.

## 후속: 연속 각도 조준·AddForce 발사

- 활·투석기 6종은 8방향 보정을 사용하지 않는다. 입력 승인 시 선택한 마우스 월드 좌표를 보관하고, 모션상 발사 시점의 발사 위치에서 그 좌표까지의 벡터를 정규화한다. 발사 후에는 목표를 추적하지 않는다.
- Dynamic Rigidbody2D, 질량 1, 중력 배율 0.85, 선형/각 감쇠 0, 회전 고정, Continuous 충돌 설정, Interpolate를 사용한다. AddForce(direction × speed × mass, ForceMode2D.Impulse)로 기존 14타일/초 초기 속도로 발사한다.
- 플레이어와 독립된 물리 루트를 사용한다. 그림은 별도 자식으로 피벗을 보정하며, 화살은 실제 발사 각도로 회전한다. 몸체 모션의 좌우 방향도 원거리 조준 벡터를 기준으로 고정한다.
- Transform을 매 프레임 이동시키던 방식은 제거했다. 물리 업데이트마다 실제 Rigidbody2D 이전/현재 위치 사이를 CircleCast로 검사한다. 자기 투사체 콜라이더는 제외하며, 기존 중복 피격 방지·관통 수·벽 소멸·사거리·사망 정리는 유지한다. 정지한 탄이 영구 잔류하지 않도록 수명 제한도 추가했다.
- 근접·부채·채굴의 기존 방향 보정은 보존했다. 피해량·탄약·레시피·저장 데이터는 변경하지 않았다.
- 순차 CPU 컴파일 오류 0(런타임 경고 3 / 에디터 경고 38), Unity 콘솔 조회 오류 0, diff 공백 오류 없음. Unity/게임 실행·런타임 물리 검증은 수행하지 않았다.
- 플레이 확인: 10도·25도·70도 등 8방향 사이의 위치를 조준해 화살/돌이 해당 위치를 향하는지 확인한다. 이동하며 반대 방향으로 발사했을 때 몸체와 이동이 분리되는지, 가까운 목표·얇은 벽·관통 대상에서 충돌 판정이 유지되는지도 확인한다.

## 후속: 투사체 중력

- 활·투석기 모두 gravityScale=0.85로 적용했다(최초 1에서 후속 사용자 요청으로 조정). 현재 프로젝트 Physics2D 중력 (0, -9.81)을 그대로 사용하며 전역 중력과 플레이어 물리는 변경하지 않는다.
- 발사 방향은 마우스 조준 방향이고, 발사 후 중력 때문에 아래로 휘어진다. 에임 위치에 자동으로 맞추는 탄도 보정은 없다.
- 화살 그림은 매 물리 업데이트의 실제 속도 방향으로 회전한다. 회전할 때 그림 중심도 다시 맞춰 충돌 원과 어긋나지 않도록 한다. 돌 그림의 회전 방식은 보존한다.
- 기존 이동 구간 충돌 판정이 굽은 궤적의 실제 물리 이동을 따라간다. 사거리는 이동 거리 누적값이며, 수명 제한과 관통·벽 충돌·탄약 처리를 유지한다.
- 직접 플레이 확인: 수평 발사한 화살·돌이 낙하하고, 위로 쏜 탄이 아래로 휘어지는지 확인한다. 화살 방향이 궤적을 따라 바뀌며 낙하 중 지형·몬스터 충돌도 유지돼야 한다. 낙하량·조준 감각은 런타임 미검증이다.

## 후속: 발톱 상태에서만 채굴

- 장비 보유·방어구 착용 여부가 아니라 ActiveSlot.IsUsingEquippedItem으로 Q 스왑 상태를 판정한다. 활성 장비 사용 상태에서는 채굴하지 않고, 발톱 상태에서만 기존 발톱 등급에 따라 채굴한다.
- 좌클릭 입력 분기, TickMining 진입, 채굴 대상 강조 표시를 동일 조건으로 차단한다. 삼나무·삼줄기·잔해·설치물·전경 타일의 공통 채굴 입구에 적용한다.
- 채굴 도중 장비 상태로 전환하면 누적 진행과 강조를 즉시 취소한다. 활 발사와 부채·방망이 공격은 유지한다. 장비 상태에서 대상 찾기나 도구 등급 부족 메시지도 채굴 경로로 발생시키지 않는다.
- CPU 런타임·에디터 순차 컴파일 오류 0(경고 3 / 38), MCP 콘솔 조회 오류 0, diff 공백 오류 없음. 런타임 미검증.
- 직접 확인: 활을 활성화하고 삼나무·흙·설치물 앞에서 좌클릭해도 강조·채굴 진행·채굴 실패 메시지가 없어야 한다. Q로 발톱 전환 후 같은 대상은 정상 채굴돼야 한다. 채굴 중 Q로 장비 전환하면 진행이 중단되고, 다시 발톱으로 돌아오면 새로 시작해야 한다.

## 후속: 부채 F 바람 이펙트

- 사용자 확인: 일반 공격과 F 능력은 몸체 모션을 공유하며, F에만 부채 바람 이펙트가 추가된다.
- 원본: 대경잼해커톤-20260725.zip / 대경잼해커톤/Effect/바닥_바람_부채용.aseprite. 최신 전달 ZIP에서 이 파일의 새 원본은 확인되지 않았다. 원본을 Assets/Art/Gameplay/fan_wind.aseprite로 복사했다.
- SHA256: 1d0317066ef8fb33b0eae800317b4298708f9a291b2ee5e2f96541efdfc88f54.
- GameplayArtCatalog.fanWindFrames에 5프레임을 연결했다. ApplyFanWindArt는 이 항목만 갱신한다.
- TryFanAbility에서 wireSnare.TryUse 성공 시에만 호출한다. 좌클릭·쿨타임 중 실패에는 호출하지 않으며, 피해·넉백·쿨타임을 추가로 적용하지 않는다.
- 몸체가 부채를 펼치는 0.2초 후 발 앞쪽에 생성하고, 원본 순서로 프레임당 0.1초 재생 후 제거한다. 원본의 오른쪽 진행을 공격 방향에 따라 좌우 반전한다. 생성 후 플레이어 이동을 따라가지 않는다. 사망·삼킴 시 중단하며 타이틀 전환 시 씬과 함께 제거한다.
- Unity MCP로 실제 카탈로그 5프레임의 원본 경로, PPU 16, Point 필터를 확인했다. 플레이 모드 종료 상태에서 임포트·저장했다.
- CPU 런타임·에디터 순차 컴파일 오류 0(경고 3 / 38). Unity 콘솔 오류 0. 실제 플레이·렌더링은 미검증이다.
- 직접 플레이 확인: 철선 등으로 좌클릭하면 몸체 모션만, F를 누르면 몸체+바람이 나와야 한다. 좌우 방향·바닥 높이·원본 5프레임의 자연스러운 소멸을 확인한다. F 쿨타임 중 추가 이펙트가 나오거나 바람 때문에 피해가 두 번 발생해서는 안 된다. 합죽선은 기존처럼 F 전용이다.

### 부채 바람 위치 보정

- 무기별 RangeTiles를 F 승인 시 보관한다. 좌우 사거리 끝 좌표는 생성 시 플레이어 X ± 사거리다.
- 각 프레임의 실제 Sprite.bounds.max.x를 사용해, 반전된 왼쪽 또는 원본 오른쪽의 전방 끝이 사거리 끝에 닿도록 배치한다. 잘린 프레임의 폭·피벗 차이를 반영하며 아트 크기와 타격 판정은 변경하지 않는다.
- 세로 위치는 collider 바닥 +0.02에서 바닥 -1/16로 내렸다. 기존보다 0.0825타일 낮다. 원본 마지막 프레임의 잔여 바람이 올라가는 움직임은 보존한다.
- 원본 프레임 전방 범위와 좌우 반전 계산 정적 검토, CPU 런타임·에디터 순차 컴파일 오류 0(경고 3 / 38), Unity 콘솔 조회 오류 0. 실제 렌더링은 미검증이다.
- 직접 확인: 2칸 부채, 4칸 채찍선, 3칸 한파 부채에서 바람 끝이 각 사거리와 일치하는지 좌우로 확인한다. 바닥에서 뜨거나 지나치게 파묻히지 않는지도 확인한다.

### 부채 바람 속도 조정

- 최종 요청에 따라 바람만 프레임당 0.15초로 조정했다(기존 0.1초와 느리게 조정했던 0.2초의 중간값). 5프레임 전체 재생은 0.75초다.
- 시작 지연 0.2초, 몸체 모션, F 쿨타임, 피해 판정과 위치는 유지한다. 원본 Aseprite 프레임 시간은 수정하지 않는다.
- CPU 런타임·에디터 순차 컴파일 오류 0. 실제 재생 체감은 런타임 미검증이다.

### 부채 넉백 속도 조정

- 부채 일반 공격과 F 능력 모두 넉백 시간을 기존 0.24초에서 0.36초로 늘렸다(1.5배). 이동 거리는 유지하고 속도는 기존의 2/3가 된다. 채찍선의 끌어당김에도 같은 시간 배율을 적용한다.
- 부채 ID일 때만 Health→WorldMobPhysicsBody에 시간 배율을 전달한다. 기존 1인자 API는 배율 1로 유지해 다른 무기·투사체·보스 공격 넉백에는 적용하지 않는다. 넉백 면역·벽 충돌 중단·거리 및 기존 아티팩트 알림을 보존한다.
- 일반 Rigidbody2D만 있는 임시 객체의 기존 impulse fallback은 변경하지 않았다. 실물 요괴는 WorldMobPhysicsBody의 거리 기반 넉백 경로를 사용한다.
- 일반 공격/F의 넉백 거리 구분은 이번 요청 범위에서 변경하지 않았다. 한파 부채 F 거리의 별도 기획 확인은 여전히 필요하다.
- 공통 전투 Health/MeleeArcAttack과 몹 물리 WorldMobPhysicsBody에 API 추가가 있으므로 팀 병합 시 해당 파일을 확인한다. 저장 데이터는 변경하지 않는다.
- CPU 런타임·에디터 순차 컴파일 오류 0(경고 3 / 38), Unity 콘솔 조회 오류 0, diff 공백 오류 없음. 실제 플레이는 미검증이다.
- 직접 확인: 부채 일반 공격과 F로 민 몹이 같은 거리까지 더 천천히 이동하는지, 벽에서 멈추는지 확인한다. 발톱·방망이·화살 넉백 속도는 기존대로여야 한다.
