## 사용하지 않은 2개

- `HypothermiaStatus_Icon2`: 사용자 선택은 1안이므로 교체하지 않음.
- `icon/t_altar_icon`: 월드 제단 아이콘이며 현재 대응 설치 아이템 슬롯이 없음. `ice_altar_offering`은 소환 재료이므로 임의 동일시하지 않았다. 월드 제단의 큰 그림도 작은 아이콘으로 대체하지 않았다. 추후 제단 아이콘을 사용할 UI 슬롯이 정해지면 연결 가능.

34개 원본 전체는 `nnnnnn_원본/`에 수정 없이 보존했다.

## 잘림 방지 및 재연결 보호

- 포대 2종·신기전 화차·이정표 4개는 헤더 캔버스 밖에 그림이 있었다. 작업 사본의 캔버스를 셀 전체 범위로 넓히고 셀을 동일하게 평행 이동했다. 포대는 공격 프레임까지 포함해 캔버스 32×32, 화차 28×32, 이정표 16×32다. Sprite 기본 프레임은 포대/화차 28×32, 이정표 14×32(투명 좌우 여백 제외)로 확인했다.
- 원본과 작업 사본의 차이를 역변환해 바이트 단위로 대조했다. 일반 28개는 파일 전체 일치, 큰 아이콘 4개는 헤더 크기/셀 좌표 외 모든 바이트 일치. 프레임 픽셀·압축 데이터·시간·태그는 유지됐다.
- 메타데이터는 연결된 Unity의 Aseprite 임포터로 설정했다. `.meta`는 직접 편집하지 않았다.
- `NyangbingoTileArtIntegrator.ItemArtFiles`, `NyangbingoArt720Binder.ItemBindings/SpriteBindings`를 최신 원본 경로로 수정했다. 받은 장비 15개를 미제공 해제 목록에서 제거해 추후 재연결 시 지워지는 것을 방지했다. 미제공은 `vault_seal`만 유지한다.

## 검증과 후속 확인

- Unity MCP로 30개 아이템의 최종 Sprite 참조를 코드 갱신 후 다시 조회했다. 중복 ID 없음. 사망 주머니·저체온 원본 경로, 눈물 HUD 4프레임의 공통 원본도 확인했다.
- 디스크 ItemArtCatalog의 172개 항목 중 171개 연결, 미연결은 창고 봉인 1개다. 이 수는 카탈로그 항목 수이며 게임 아이템 SO 수와 구분한다.
- CPU C# 런타임→에디터 순차 컴파일: 오류 각 0개, 경고 3/38개. 변경 코드의 `git diff --check` 통과.
- 검증은 원본 대조·임포트/참조 확인·정적 검토·CPU 컴파일이다. Unity/게임을 새로 실행하거나 플레이 모드·GPU 검증을 수행하지 않았다.
- 사용자는 인벤토리·장비탭·제작 목록·드롭의 새 아이콘, 포대 기본 그림/이정표 기둥 잘림 여부, 눈물 증가 시 4프레임, 사망 주머니 수량 및 회수를 실제 플레이에서 확인해야 한다.
