# 월드 아트 잘림 정적 조사 — 2026-10-04

## 확인 결과

- 사용자 확인: 인벤토리 아이콘이 아닌 월드에서 자라는 모습이 잘려 보임.
- Buildings/Decorations/Tiles의 Aseprite 64개, Unity Sprite 72개를 MCP로 읽어 원본 크기/PPU와 메시 범위를 대조했다. 메시 가로·세로가 Sprite 영역보다 작게 생성된 항목은 0개다.
- 단일 프레임 원본 61개는 불투명 픽셀 경계와 임포터의 cellRect가 모두 일치했다. 자동으로 제거한 투명 여백은 그림 잘림으로 판단하지 않았다.
- 삼줄기: 교체 전/현재 모두 16×16, 현재 불투명 영역 16×12. Unity Sprite 영역 16×12, PPU 16, 메시 1×0.75칸으로 원본 영역을 전부 포함한다.
- 현재 삼줄기 원본 확대: [PNG](삼줄기_현재원본_확대.png). 새 아트 생성이나 Assets 스프라이트 수정이 아닌 기존 원본 확인용 확대 그림이다.
- WorldDecorationRenderer.CreateHempPatch는 SpriteRenderer를 사용하고 월드 셀 바닥에 bounds로 정렬한다. 한 칸 크기로 sprite를 자르거나 축소하는 처리는 없다. 설치물도 동일한 bounds 바닥 정렬 경로를 사용한다.
- 후속 사용자 화면과 배선을 대조해 나무 조각이 독립 나무 종류로 생성되는 원본 선택 오류를 확인했다. 크기·메시 검사만으로는 이 잘못된 원본 선택을 찾아내지 못했다.

## 검증 수준 및 남은 확인

- 원본 픽셀/임포터 직렬화 자료 대조, Unity 에디터 Sprite 데이터 조회 및 코드 흐름 검토 완료.
- Unity/게임 실행, 플레이 모드 테스트, GPU 검증 없음. 조회 당시 Unity는 Title 씬·플레이 모드 비활성이었다.
- 후속 수정: WorldDecorationArtCatalog의 tree_1/tree_2를 tree_0과 같은 완성형 tree.aseprite로 연결하고, NyangbingoTileArtIntegrator의 재연결 경로를 일치시켰다. 원본 픽셀·메타·씬·생성 로직·저장 ID는 변경하지 않았다.
- CPU C# 빌드 순차 수행: 런타임 오류 0, 에디터 오류 0/경고 38. Unity MCP로 나무 3개 ID의 완성형 Sprite 참조와 불투명 높이 29px을 검증했다.
- 후속 플레이 확인: 새 게임 또는 이어하기로 월드 장식을 다시 생성한 뒤, 짧은 나무 조각 대신 완성형 나무가 나타나는지 확인 필요. 게임 실행/플레이 모드 테스트는 수행하지 않았다.

## 사용자 화면 대조와 수정 근거

- 사진 1의 삼줄기는 현재 납품 원본 전체 모양과 일치한다. 인위적으로 크게 늘리거나 새로운 그림을 만들지 않았다.
- 사진 2와 같은 짧은 줄기는 독립 나무 종류로 연결돼 있던 tree_down/tree_up 조각이다. 사진 3처럼 완성형 t_tree를 모든 tree_0/tree_1/tree_2에 사용하도록 수정했다.
- 생성 코드는 random.Next(3)으로 세 ID를 선택한다. 이 선택이나 난수 소비를 바꾸면 이어하기의 식생 위치/ID에 영향을 줄 수 있으므로 표시 배선만 수정했다.
- 두 조각 파일은 보관하며 독립 나무 배선에서 제외했다. 납품본에 다른 완성형 변형이 없어 현재 세 나무 ID의 외형은 동일하다.
- 제단 조각은 TilemapRenderer.ResolveIceAltarTile의 4분할 배열을 통해 조합된다. 나무처럼 부분 원본을 완성 오브젝트의 다른 종류로 선택하는 경로와 구분했다.
- 파란 채굴 강조는 선택된 논리 셀 단위 표시다. 이번에는 강조 효과 크기나 채굴 범위를 변경하지 않았다.
