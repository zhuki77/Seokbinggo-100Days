# 10-4 추가 납품 아트 적용 결과

최신 정본: `D:/다운로드/박태영/대경잼/10-4작업.zip`. 사용자 확인에 따라 지귀의 재/잉걸을 바로잡고 포대·화차 발사 프레임을 연결했다. 미장이 인형 아이콘은 전체 1×2 원본을 재사용한다. 현재 브랜치의 기존 변경사항을 유지했다.

## 적용 내역

| 대상 | 월드/아이콘 연결 | 동작 |
|---|---|---|
| 한파 포대 `cold_wave_battery` | 새 설치 원본, 기본 프레임을 아이콘 공유 | 기본 Frame_0, 발사 Frame_1→2→3 |
| 도관 포대 `ice_root_battery` | 새 설치 원본, 기본 프레임을 아이콘 공유 | 기본 Frame_0, 발사 Frame_1→2→3 |
| 신기전 화차 `singijeon_cart` | 기존 설치 원본 교체 | 기본 Frame_0, 발사 Frame_1→2→3 |
| 미장이 인형 `plaster_doll` | 새 전체 원본을 월드/아이콘 공유 | 정지 1프레임. 부분 그림 1·2 제외 |
| 지귀의 재 `jigwi_ash` | 새 재 아이콘으로 교체 | 기존에 잉걸 그림이 들어 있던 연결 수정 |
| 지귀의 잉걸 `jigwi_ember_mat`, `jigwi_ember` | 재료와 아티팩트 모두 납품 잉걸 원본 공유 | 다른 대상 그림 대체 없음 |
| 영노의 탈 `yeongno_mask_mat`, `yeongno_mask` | 재료와 아티팩트 모두 납품 탈 원본 공유 | 다른 대상 그림 대체 없음 |
| 신기전 손대, 한파 신기전 | 각각 전용 아이콘 연결 | 이름이 같은 해당 원본 사용 |
| 느타리, 표고 | 새 block 원본을 월드에 연결 | 기존 전용 인벤토리 아이콘 유지 |
| 석이 `seogi` | 월드/아이콘 각각 별도 납품 원본 연결 | Tile 에셋과 MainGame 매핑 추가 |
| 성에 광석 | 기존 동일 원본 유지 | SHA256 동일하므로 중복 교체 없음 |

16개 납품 중 13개 원본을 적용했다. 미장이 인형 부분 그림 2개는 사용자 지시로 제외하고 성에 광석 1개는 이미 동일 원본이다. [적용 원본 13개 SHA256](10-4_적용_원본_SHA256.csv)에 ZIP 대응 경로와 해시를 기록했다.

## 캔버스와 실제 그림 크기 정정

첫 수신 보고서의 미리보기는 파일 캔버스만 표시했다. Unity 임포트와 원시 셀 대조로 캔버스 밖 그림을 추가 확인했다.

- 포대·화차: 캔버스 32×16, 기본 셀 실제 27×32px. 잘라내지 않고 전체 그림을 보존했다. 발사 셀은 27×32, 23×32, 24×32px이며, 원본 셀의 x 좌표 5/5/9/8을 고려해 동일 기준점으로 피벗을 맞췄다. 프레임별 잘림 폭 때문에 본체가 옆으로 흔들리지 않도록 했다. 설치 점유·충돌·사거리 수치는 변경하지 않았다.
- 느타리·표고: 파일 캔버스 16×16이지만 실제 셀은 64px 너비의 개별 그림 4종이다. Aseprite 임포터의 EditSpriteRect 지원이 없어 자르기를 강제하지 않았다. 원본 캔버스를 그대로 PNG로 추출해 16×16 Tile Sprite로 연결했다. 느타리는 셀 x=-16에 대응하는 두 번째 16px 구간, 표고는 x=0에 대응하는 첫 구간이다. 원본 픽셀을 새로 그리거나 보정하지 않았으며 4종 원본도 보존했다.
- 미장이 인형: 캔버스 16×32, 투명 여백이 잘린 실제 Sprite는 16×31px. 아이콘은 이 전체 Sprite를 사용한다.
- 모든 새 월드 Sprite는 16 PPU, Point 필터, 하단 기준 피벗이다.

## 발사 연결 및 담당 경계

BuildingArtCatalog에 대기 Frames와 AttackFrames를 분리했다. World의 실제 Fired 이벤트가 발생하면 RuntimeBuildingSpriteAnimator.PlayOnce로 발사 3프레임을 각각 0.1초 재생하고 Frame_0으로 돌아간다. 재발사 시 처음부터 다시 재생한다. 대기 상태에서 공격 프레임을 반복하지 않는다.

A+C 월드 표시·아트 연결 도구를 수정했다. B 전투 서비스·피해량·연료·발사 조건은 수정하지 않았다. 기존 저장 좌표와 저장 형식에도 변경을 추가하지 않았다. 카탈로그와 MainGame 씬은 공유 파일이므로 후속 병합 시 충돌 가능성을 확인해야 한다. MainGame에는 석이 매핑만 추가했고, Unity 저장 과정에서 생긴 무관한 기본 필드 직렬화는 제거했다.

## 수행한 검증과 한계

- ZIP과 적용한 원본 13개 SHA256 일치 확인. 기존 Tile 에셋 참조는 유지하고 석이만 신규 생성했다.
- Unity MCP로 6개 카탈로그 Sprite 필드 580개 전수 조회: 564개 참조 정상, 미제공 아이콘 16개만 의도적으로 비어 있다. [전수 결과](10-4_카탈로그_Sprite_580개_전수목록.csv).
- BuildingArtCurrent 확인 및 Building Art 정적 검증 통과: 기본/발사 개수, Frame 이름, 실제 원본 경로 확인.
- Unity 소스 Refresh 후 연결 도구 정적 검증 통과: Tile 28/28, Building 50종, Item 도구에 등록된 101/101. 전체 게임 아이콘 170종은 별도 전수 CSV로 대조했다.
- 아이콘 11개 변경 대상의 FindSprite 실제 응답 확인. [아이템 170종 목록](아이템_170종_아트_연결_전수목록.csv) 갱신.
- CPU C# 런타임→에디터 프로젝트 순차 컴파일, 오류 0개. 기존 에디터 obsolete 경고는 남아 있다.
- 발사 후 기본 복귀와 저장 좌표 보존은 코드 흐름으로 검토했다. Unity·게임 실행, 플레이 모드, GPU 검증은 하지 않았다. 실제 발사 모습·인벤토리 표시·기존 세이브 로드는 런타임 미검증이다.
- `git diff --check`는 Unity가 생성한 Sprite 메타데이터의 빈 YAML 값 뒤 공백을 보고한다. 메타데이터를 수동 수정하지 않고 유지했다. C# 컴파일 오류와는 별개다.

후속 플레이 확인: 포대 2종/화차 발사 1회 후 기본 복귀, 미장이 인형의 전체 아이콘 표시, 느타리·표고의 한 칸 표시, 석이 월드/습득 아이콘을 확인한다.
