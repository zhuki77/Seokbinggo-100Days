# 로프 구현 및 확인 안내 — 2026-10-05

## 요청과 구현 범위

기획자 신규 요청: 테라리아의 밧줄처럼 수직굴을 오르는 로프. `rope.zip`의 원본을 사용하며 후속 확정: 나무 1개→로프 1개, 제작대 없이 즉시 손 제작한다.

현재 브랜치: `feat/taeyo-ingame-interaction-polish`. 기존 미커밋 작업을 보존했다. 플레이어·월드·데이터·아트 카탈로그는 공유 파일이므로 후속 병합에서 겹치는 변경을 확인해야 한다.

| 항목 | 구현 |
|---|---|
| 아이템 | 로프 / `rope` / placeable / 99개 스택 / A |
| 설치 | 기존 퀵슬롯 타일 설치 방식. 첫 칸 바로 위에 충돌 타일 필요. 고정된 로프 아래로만 연장. 플레이어 겹침 허용, 기존 사거리·장식 점유·선택 스택 소비 적용 |

로프 끝을 지나거나 몸에 닿는 로프가 없어지면 일반 이동으로 돌아간다. 넉백·삼켜짐·사망·위치 복원에도 매달림 상태가 남지 않도록 정리한다. 메뉴를 열면 수직 이동을 멈춘다. 로프에서 이탈한 위치부터 낙하 거리를 새로 계산한다. 위치를 강제로 순간이동시키지 않고 Rigidbody 속도로 로프 중심에 접근하므로 기존 벽·천장 콜라이더를 유지한다.

## 원본 및 연결 확인

- ZIP: `D:\다운로드\박태영\대경잼\rope.zip`.
- `rope.aseprite`: 원본 16×16, 1프레임. `Assets/Art/Tiles/rope.aseprite`에 그대로 복사.
- `Player_rope.aseprite`: 원본 32×32, 4프레임. `Assets/Art/Characters/player_rope.aseprite`에 그대로 복사.
- SHA-256으로 두 파일 모두 ZIP과 동일함을 확인했다. 임의 그림을 만들지 않았다.
- 기존 Unity MCP에서 플레이 모드가 아님을 확인한 뒤 원본을 임포트하고 아이템·월드·플레이어 카탈로그 참조를 저장했다.
- 실제 임포트 결과: 로프 6×16 불투명 영역, 플레이어 프레임 17×30 / 17×27 / 17×27 / 17×29. 원본의 투명 여백을 제외한 영역이며 원본 픽셀을 자른 것이 아니다.
- 두 원본 모두 PPU 16 / Point / mipmap 비활성. 아이콘·월드·타일은 같은 로프 Sprite 참조. 타일 collider=None. 플레이어 로프 프레임 4개와 카탈로그 단일 등록을 저장 파일로 재확인했다.
- 에디터 아트 재연결 코드에도 로프 경로와 플레이어 로프 프레임 연결을 추가해 재적용 시 유지한다.

## 사용자가 플레이로 확인할 사항

1. `Shift+F11`으로 로프 99개를 받고 퀵슬롯에 옮긴다. 천장의 충돌 타일 바로 아래부터 8칸 이상 아래 방향으로 이어 설치한다. 선택한 스택만 1개씩 줄고 설치 미리보기와 실제 그림이 일치하는지 확인한다.
2. 로프 열에 서서 W를 누른다. 위로 올라가며 전달된 4프레임이 움직이고, 손을 놓으면 떨어지지 않고 매달리는지 확인한다. S로 내려간다.
3. 좌우 이동과 Space로 이탈한다. 손을 뗀 후 W/S로 다시 잡히는지 확인한다. 윗단에서 Space/좌우로 발판에 올라가는 동선도 확인한다.
4. 벽·천장·바닥 옆에서 이동해 충돌을 뚫지 않는지, 로프 끝·끊긴 구간에서 정상적으로 이탈하는지 확인한다.
5. 매달린 상태에서 인벤토리·일시정지를 열었다 닫는다. 화면 뒤에서 계속 오르지 않는지 확인한다. 이탈 후에는 정상 낙하가 적용되는지 확인한다.
6. 로프를 채굴한다. 그림이 사라지고 로프 아이템으로 드롭되며 습득 시 인벤토리에 들어오는지 확인한다.
7. 로프가 설치된 월드를 저장하고 타이틀→이어하기로 복원한다. 설치 위치·수량·통과·재등반을 확인한다. 매달림은 저장하지 않으므로 이어하기 후 W/S로 다시 잡는다.

런타임 이동 감각·프레임 정렬·물리 충돌·실제 저장 왕복은 미검증이다. 후속 기획 결정은 전용 등반 속도이며, 제작법은 나무 1개→로프 1개 즉시 손 제작으로 확정됐다.

## 후속 확정 조건 적용 — 2026-10-05

- 충돌 없는 전경 타일은 플레이어와 겹쳐 설치할 수 있다. 다른 장식의 점유 차단은 유지한다. 일반 고체 타일과 문은 플레이어 겹침을 계속 차단한다.
- 로프 첫 칸은 바로 위 충돌 타일이 필요하다. 버섯 등 통과 타일, 공기, 배경, 열린 문을 지지대로 인정하지 않는다. 기존 로프 아래로 연장할 때도 위로 따라가 실제 충돌 타일에 고정된 줄인지 확인한다.
- 설치 미리보기와 실제 설치는 동일 CanPlaceForeground 판정을 거치며, 실패하면 아이템을 소비하지 않는다.
- 로프 중간 채굴 시 해당 칸과 바로 아래로 이어진 모든 칸을 제거한다. 위쪽과 옆의 줄은 유지한다. 회수 수량은 끊은 칸 1개+아래 제거 개수이며 기존 월드 드롭 경로를 사용한다. 설치한 로프는 크리티컬로 복제되지 않는다.
- 지지 타일을 채굴·파괴해 제거한 경우에도 아래 로프가 떨어진다. 문 상태 복원처럼 이벤트 없는 데이터 정리에는 추가 드롭을 만들지 않는다.
- 제거한 각 칸마다 changeLog에 기록한다. RestoreTileChanges는 이력을 그대로 재생하며 연쇄 제거를 다시 호출하거나 드롭을 다시 만들지 않는다.
- 제작 CSV와 Recipe SO를 모두 등록했다. 재료 wood:1, 출력 rope:1, station=None, durationSeconds=0, scope=A. 실제 SO의 wood/rope GUID와 카탈로그 단일 등록을 대조했다.
- CPU 런타임·에디터 순차 컴파일 오류 0. 실제 플레이·제작·회수·저장 왕복은 미검증.

### 추가 플레이 확인

1. 제작대에서 떨어진 곳에서 C 제작창을 열고 로프를 선택한다. 나무 1개가 줄고 로프 1개가 즉시 지급되는지 확인한다.
2. 공중 첫 설치와 버섯 아래 설치는 불가인지 확인한다. 돌 천장 바로 아래는 가능이어야 한다.
3. 해당 로프 아래로 연장한다. 옆의 공중에는 설치할 수 없어야 한다. 몸이 겹쳐도 로프는 설치되고 고체 흙·돌은 차단되는지 확인한다.
4. 8칸 줄의 위에서 세 번째 칸을 캐면 6개가 드롭되고 위 2칸이 남는지 확인한다. 남은 줄 아래로 다시 이어 붙인다.
5. 절단·회수 후 저장→이어하기에서 제거된 아래 구간이 되살아나지 않고 남은 위쪽만 복원되는지 확인한다.
