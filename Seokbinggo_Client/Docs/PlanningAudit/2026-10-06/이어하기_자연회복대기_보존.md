# 이어하기 자연회복 대기 보존

2026-10-06 사용자 확정: 저장 당시 남은 대기 시간을 이어하기에서 유지한다.

- 원인: MainGameSaveCoordinator가 매번 ResetAfterRestore를 호출해 마지막 피해 이후 경과 시간을 0으로 되돌렸다. BedService는 IsNaturalRecoveryReady를 휴식 조건으로 사용하므로 이미 휴식 가능한 저장도 불러오기 직후 10게임초 동안 차단됐다.
- PlayerStateRecord에 hasNaturalRecoveryState, naturalRecoveryDelayRemaining, naturalRecoveryFractionalHealing을 추가한다. 저장은 남은 대기와 소수 HP 회복 누적량을 캡처하고, 복원은 플레이어 체력 복원 직후 해당 값을 복구한다. 무조건 초기화 호출은 제거한다.
- 대기 중 저장은 남은 시간만 기다린다. 회복 가능 저장은 이어하기 직후에도 가능하다. 최대 체력에서도 같은 기준을 사용하며, 복원 후 새 피해는 정상적으로 전체 대기를 다시 시작한다. 불러오기 중 현실 시간은 대기에서 차감하지 않는다.
- 구 세이브의 필드 누락은 hasNaturalRecoveryState=false로 구분한다. 과거 피격 시간을 추정할 수 없어 기존 10게임초 대기를 유지한다. 새 저장부터 상태가 기록된다.
- 잘못된 비유한값·음수·범위를 벗어난 소수 누적량은 복원 실패로 처리한다. 저장 적용 실패의 기존 롤백 캡처에도 회복 상태가 포함된다.
- 남은 6초 유지, 회복 준비 유지, 소수 회복 유지, 최대 체력 휴식, 잘못된 입력 보존, 구 저장 호환 및 재피격 초기화의 회귀 테스트를 추가했다. 실행은 하지 않았다.
- CPU C# 컴파일: 런타임/에디터 모두 오류 0개. Unity/게임 실행 및 GPU 검증은 수행하지 않았다. Unity 콘솔에 남은 guideDay 0→1 저장 왕복 불일치는 이번 수정 범위와 별개다.
