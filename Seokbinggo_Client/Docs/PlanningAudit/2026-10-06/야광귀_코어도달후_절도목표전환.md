# 야광귀 코어 도달 후 절도 목표 전환

2026-10-06 사용자 확정: 닫힌 문에 막히는 동작은 의도된 사항이다. 코어에 도달한 야광귀만 기존 절도형 목표로 전환한다.

- `MainGameCoreRaidTarget`가 기존 플레이어 목표를 `IYokaiCoreTheftTarget.TheftTarget`으로 제공한다. 코어 접근 단계에는 기존 경로·벽 충돌·벽 피해 0을 그대로 사용한다.
- `YokaiBrain`은 야광귀에 한해 기존 도달 사거리와 `HasClearAttackLine`을 함께 확인한 후 목표를 전환한다. 닫힌 문/벽 너머의 단순 근거리에서는 전환하지 않는다. 체 정지 및 강제 어그로 중에는 해당 행동이 끝난 뒤 도달 판정을 수행한다.
- 전환 후 절도 상태가 플레이어 목표의 `IYokaiAtomicLootTarget`을 사용한다. 바닥 드랍 절도 우선, 인벤토리 절도 순서를 유지하고 절도품 기록을 완료한 경우에만 절도 도주한다. 도달 시 플레이어와 이미 교전한 상태로 처리하며, 다른 요괴의 목표는 변경하지 않는다.
- 침공 중에는 코어 도달 시 기존 침투 기록을 한 번 시도한다. 절도 목표로 전환하면서 즉시 도주하지는 않는다.
- 개체 저장에 `hasReachedCoreForTheft`를 추가한다. 기존 저장 파일의 필드 누락은 false로 읽으며, 새 저장에서는 전환 여부를 보존한다. 복원은 기존 행동 상태(절도·도주 등)를 유지하면서 플레이어 목표를 다시 연결한다.
- 런타임·에디터 CPU C# 컴파일 및 정적 코드 흐름으로만 검토했다. 게임/Unity 플레이 및 GPU 검증은 수행하지 않는다.

## 절도품 유실 및 즉시 재절도 방지 후속 수정

- 바닥 절도 기준점을 플레이어에서 해당 야광귀로 바꾸고 기존 공격 사거리 안의 드랍만 선택한다. 맵 전체의 먼 아이템을 제거하지 않는다.
- 인벤토리와 바닥 드랍 모두 실제 야광귀의 `YokaiLoot`가 유효한 아이템·수량 전체를 수락한 뒤 원본을 제거한다. 기록 실패/수신자 누락 시 원본과 인벤토리 변경 알림을 보존한다.
- 절도 도주에는 성공 응답과 개체의 절도품 보유를 모두 요구한다. 낮이 되어 도주하는 별도 동작은 유지한다.
- 처치로 돌려주는 실제 절도품만 재절도 방지 드랍으로 생성한다. 플레이어/까치의 회수는 가능하며, 수거되기 전까지 다른 야광귀가 가져가지 않는다. 일반 드랍/눈물/보따리에는 적용하지 않는다.
- `WorldDropStateRecord.theftProtected`에 해당 보호 상태를 저장·복원한다. 기존 세이브에 없는 값은 false로 읽는다.
- 기록 거부 시 원본 보존, 변경 알림 전 절도품 기록, 거리 제한, 반환품 보호 및 저장 복원, 처치 시 전량 반환에 대한 회귀 테스트를 추가했다. 테스트 실행 및 실제 플레이 검증은 수행하지 않았다. CPU C# 컴파일은 런타임/에디터 오류 0개로 통과했다.
