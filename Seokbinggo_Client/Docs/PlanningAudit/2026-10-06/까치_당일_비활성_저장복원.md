# 까치 당일 비활성 상태 저장·복원

2026-10-06 사용자 재현: 밀폐 해제 → 까치 비활성화 → 당일 밀폐 복구 → 저장·불러오기 → 다음 아침 전 까치가 활동하는 문제.

원인: Capture는 입주/처치/백중/둥지/보관함만 저장했다. Restore는 `joined && 현재 기능성 둥지`로 활동을 새로 계산하여 Tick이 해제했던 당일 활동 허가를 되살렸다.

- SaveGame.magpieActiveForDay 추가, 스키마 30→31.
- Capture는 입주 완료·당일 활동 허가·현재 밀폐 둥지 조건을 모두 만족할 때만 활동 상태를 저장한다. 개발용 강제 활성 오버라이드는 저장하지 않는다.
- Restore는 저장된 활동 상태를 그대로 요구하고 현재 둥지 조건도 확인한다. 밀폐 복구만으로 false를 true로 바꾸지 않는다.
- 재활성화는 기존 HandleDayStart의 다음 아침 처리에서만 허용한다. 24시간 타이머를 새로 추가한 것이 아니다.
- 스키마 30 이하에는 당일 비활성 여부가 없으므로 활동을 추정하지 않고 false로 이관한다. 기존 입주 여부·처치 수·백중 기록·보관함은 보존하고 다음 아침에 정상 재평가한다. 새 스키마의 활성 저장은 조건이 유지되면 활성으로 복원한다.
- 기존 Editor JSON 회귀 검사에 활성/비활성 왕복과 구 저장 보수적 이관 검사를 추가했다. 이 검사는 CPU 컴파일로 참조만 확인했으며 Unity에서 실행하지 않았다.
- CPU C# 컴파일: 런타임 오류 0/경고 3, Editor 오류 0/경고 38. Unity/게임 신규 실행·플레이 모드·GPU 검증 없음.

사용자 확인:
1. 활성 까치의 둥지 방을 미밀폐로 만들어 비활성화 확인.
2. 같은 날 밀폐 복구 → 즉시 재활성화되지 않는지 확인.
3. 저장→불러오기 → 여전히 비활성인지 확인.
4. 밀폐를 유지한 채 다음 아침 → 재활성화 확인.
5. 새 버전에서 활성 상태로 저장→불러오기 → 활성 상태 유지 확인.
