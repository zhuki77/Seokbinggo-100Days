# 버섯 지지층과 생성 판정

2026-10-06 사용자 요청: 느타리·표고 등 버섯은 삼나무·삼줄기처럼 통과 가능하며, 지지층 파괴 시 함께 부서져 드랍한다. 자연 생성에서 버섯을 지지대로 삼지 않지만, 기존 지형의 동굴 끝 한 칸 공간은 허용하고 플레이어는 버섯 위 칸에 블록을 설치할 수 있다.

- 느타리·표고·석이의 기존 비충돌 판정을 유지한다.
- TileService의 채굴, 실제 전경 제거, 벽 내구도 파괴 경로에서 바로 위 버섯의 지지 상태를 검사한다. 지지층이 사라졌으면 버섯도 제거하고 기존 아이템·수량 정의로 월드 드랍한다. 제거 이력과 TileBroken 이벤트를 남긴다. 이벤트 없는 문 데이터 복원은 추가 드랍을 발생시키지 않는다.
- 자연 캣닢 생성의 동굴 바닥 후보를 실제 충돌 지지층으로 제한한다. 다른 식물의 공통 지지층 및 지표 탐색도 같은 조건을 사용하므로 버섯·로프는 자연 식물의 바닥이 되지 않는다.
- 버섯은 최종 동굴 지형 생성이 끝난 뒤 배치한다. 기존 천장을 지우거나 새 천장을 추가하지 않는다. 최소 3칸 여유 요구를 해제하고, 머리 위 공간이 있는 곳 및 좌우 끝 한 칸 포켓을 허용한다. 동굴당 2~3개 개별 생성 흐름을 유지한다.
- 수동 블록 설치는 기존 빈 칸 판정을 사용하므로 버섯 위의 빈 칸에도 가능하다. 지지층 파괴 시 그 인공 블록까지 연쇄 제거하지 않는다.
- 검증은 코드 흐름 정적 검토 및 CPU C# 컴파일이며 실제 플레이는 수행하지 않았다.

플레이 확인: 느타리·표고의 바닥을 채굴하면 버섯도 사라져 해당 아이템 드랍. 위 빈 칸에는 흙·차열벽 등을 설치할 수 있어야 한다. 새 맵에서 버섯 위에 캣닢이 생기지 않으면서 동굴 끝의 낮은 포켓 버섯은 허용되어야 한다. 기존 저장 맵에 이미 생성된 겹침은 자동 재배치하지 않는다.

## 기존 세이브 복원 호환 보완

- Unity MCP 로그에서 world session 복원 실패 확인: (298,125)의 oyster_mushroom 제거 이력이 있으나 재생성 결과는 공기였다. 현재 세이브를 읽어 resourceGenerationVersion=1 및 해당 제거 이력을 확인했다.
- 원인은 버섯 후보 공간 조건을 기존 생성 버전 1에 그대로 바꿔, 동일 시드에서도 후보와 RNG 선택 결과가 달라진 것이었다.
- 새 맵 생성 버전을 2로 올리고 버전 1은 원래의 경도 기반 바닥·위 2칸 공기 후보 조건을 정확히 유지한다. 버전 0의 기존 광맥 생성 분기도 유지한다. 세이브 파일 자체나 타일 이력을 수정하거나 삭제하지 않았다.
- 현재 저장의 생성 버전은 계속 1로 보존하며 새 게임만 2를 사용한다. 새 지지층 파괴·드랍 처리는 기존 맵에도 적용된다.
- CPU 컴파일 런타임 오류 0/경고 3, Editor 오류 0/경고 38. 실제 이어하기 실행 검증은 수행하지 않았다.
