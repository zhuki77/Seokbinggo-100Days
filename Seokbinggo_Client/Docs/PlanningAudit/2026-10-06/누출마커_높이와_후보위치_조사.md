# 누출 마커 높이와 찬바람 후보 위치 조사

2026-10-06 사용자 화면 보고: 대표 진단 마커가 0.5타일 묻힘, 찬바람 효과가 예상 밖 3곳에 표시됨.

## 현재 적용: 일반 누출 칸에 높이 보정 없이 표시

- 후속 화면에서 누출 빈 칸 위 차열벽에 마커가 뜨는 결함을 확인했다. `GetCellWorldBounds`가 이미 실제 격자 칸의 중심과 범위를 반환하는데, 일반 누출에 기존 `LeakVisualYOffset = 1`을 더해 표시가 한 칸 올라간 것이 원인이다.
- 일반 누출의 공통 표시 보정을 0으로 바꿨다. 진단 사각형/아이콘, 반복 찬바람, 해당 위치의 수리 체크가 실제 누출 칸을 가리킨다. 타일 좌표·누출 탐색·밀폐 판정은 변경하지 않는다.
- 두 칸 높이 문은 기존 기준 칸에서 반 칸 위인 문 중앙에 표시한다. 문 자체 위치를 가리키는 이전 수정은 유지한다.
- 실제 누출 칸 바로 위에 경계 벽이 있는 회귀 사례에 표시 중심이 원래 누출 칸에 속하는지 검사하는 코드를 추가했다. 게임/Unity 플레이 및 테스트 실행은 하지 않고 CPU C# 컴파일만 확인한다.

## 현재 적용: 진단 아이콘과 찬바람의 위치 통합

아래의 후보 추정·가상 수리 검증은 모두 과거 조사 기록이며 현재 구현에서는 제거했다. 찬바람의 목적은 현재 새는 위치를 안내하는 것이지, 가상 수리로 방 전체가 밀폐될 것을 증명하는 것이 아니다.

- `GetMissingBoundaryCells(core)`는 진단 아이콘이 사용하는 `TryGetCoreLeakCell(core)`의 대표 누출 칸 하나를 그대로 반환한다. 밀폐 또는 대표 누출 없음이면 빈 목록을 반환한다. 동일 누출에 대해 두 종류의 위치 선정 알고리즘을 운용하지 않는다.
- 찬바람은 해당 대표 위치에서 0.1초 간격으로 6프레임을 반복한다. 임의의 세 곳을 채우지 않는다. 타일/문 변경으로 밀폐 캐시가 무효화되면 다시 선정하며, 다른 누출이 있으면 새 대표 위치로 이동하고 밀폐되면 사라진다.
- 진단 아이콘은 기존처럼 길게 누를 때 일시 표시하며 찬바람은 안내가 보이는 동안 반복한다. 표시 시간은 달라도 동일한 누출 칸과 `GetLeakVisualYOffset`의 일반 칸 보정 0/문 중앙 보정을 공유한다. 기존 찬바람 UI에는 이 높이 보정이 빠져 있었다.
- 가상 문 닫기는 기존 문 안내에만 사용한다. 찬바람은 실제 문 상태를 포함한 현재 누출 판정을 따른다. 밀폐율·냉각·실제 타일과 문 상태는 변경하지 않는다.
- 기존 CPU 컴파일 대상 회귀 코드에 밀폐 상태의 무표시, 비밀폐 고체 경계와 외부 연결 통로에서 아이콘/찬바람 위치 일치 검증을 추가했다. 사용자 지시에 따라 회귀 코드를 실행하지 않고 런타임·에디터 C# 컴파일과 정적 흐름만 검토한다. 화면 재현은 아직 검증되지 않았다.

## 이전 조사 기록

### 단열문 자체 위치로 누출 표시

후속 오표시 확인: 기존에는 첫 번째 고체 누출을 `representativeLeakCell ??=`로 저장하고, 이후 `RecordWindowLeak`가 대표 위치 존재 시 경로의 문 조회를 건너뛰었다. 따라서 문 바깥의 비밀폐 타일이 먼저 방문되면 열린 문 우선 처리가 실행되지 않았다. 좌표 하드코딩이 아니라 탐색 순서와 조기 확정 문제다.

- 현재는 탐색 완료 후 연결된 열린 문의 실제 점유 칸을 수집한다. 그 문들을 가상으로 닫아 코어 공간이 밀폐됨을 확인하면, 실제 실내 경계에 닿는 문 중 코어에 가까운 문의 기준 칸으로 대표 누출을 확정한다. 일반 누출 좌표는 해당 조건을 만족하지 않는 경우에 사용한다.
- 가상 재탐색에서는 문 우선 검증을 다시 실행하지 않아 재귀를 막는다. 실제 문·밀폐율·냉각은 그대로다.
- 레지스트리 연결 변경 시 기존 밀폐/누출 캐시도 무효화한다. 연결 전 계산한 위치가 남지 않게 한다.
- 외부 인공 돌이 먼저 발견되는 열린 문 사례를 회귀 코드에 추가했다. 레지스트리 연결 전후 캐시와 문 기준 칸, 찬바람 위치, 문의 중앙 높이를 검증하도록 작성했다. 사용자 지시 범위상 실행하지 않고 CPU 컴파일과 코드 흐름만 검토한다.

- 문 점유 칸과 개폐 상태를 O(1) 조회하는 선택적 `ISealDoorRegistry` 계약을 추가했다. 전경 문을 열어 타일이 공기로 바뀌어도 레지스트리의 문 위치로 진단한다. 문 상단과 하단은 같은 기준 칸으로 정규화한다.
- 대표 누출 경로가 열린 단열문을 통과하면 문 바깥 공기 칸보다 문의 기준 칸을 우선한다. 비인정 고체 경계가 열린 문인 경우에도 같은 기준 칸을 사용한다. 닫힌 문은 이 우선 선정 대상에서 제외한다.
- 찬바람·누출 진단 마커·수리 체크가 공유하는 `MainGameBuildingGuide.GetLeakVisualYOffset`는 문에서 2칸 높이의 중앙을 사용하며, 일반 누출은 기존 높이 보정을 유지한다. 실제 밀폐 탐색과 냉각 판정은 바꾸지 않는다.
- 런타임·에디터 CPU C# 컴파일과 정적 검토 범위이며 플레이 확인은 필요하다.

### 고친 칸 체크 후속 수정

- 기존에는 이전 대표 누출 칸이 목록에서 사라지고 그 원래 칸이 경계가 된 경우만 수리 이벤트를 발행했다. 화면에 보정해서 표시한 위치를 막는 경우를 놓쳤다.
- 이제 진단 셀과 보정된 표시 중심에 해당하는 셀의 경계 여부를 기록하고, 비경계에서 밀폐 가능한 경계로 전환됐을 때 수리 이벤트를 발행한다. 대표 누출이 그대로이거나 다른 누출이 남아 있어도 방금 고친 안내 칸은 체크한다. 이미 존재하던 벽이나 새로 설치한 비밀폐 흙/돌에는 체크하지 않는다.
- 이벤트는 실제로 변경된 셀과 표시 높이 보정을 함께 전달한다. 찬바람이 표시되던 중심에 녹색 체크를 0.9초 표시한다. 단열문만의 닫힘 체크는 기존 위치를 유지하며 같은 문의 상·하단으로 중복 발생하지 않도록 한다.
- 저장 복원·코어 변경·첫 평가에서는 기존 상태를 다시 기록하며 수리 이벤트를 발생시키지 않는다. 실제 밀폐 판정 및 냉각 규칙은 그대로다.
- CPU C# 컴파일 및 정적 흐름 검토 범위다. 게임 실행은 하지 않았다.

- 요청된 높이 수정: MainGameHudController.SealLeakMarkerVisualYOffset를 0.5에서 1로 변경했다. 대표 누출 칸의 사각 테두리와 정적 마커를 함께 기존보다 0.5타일 위로 올린다. 누출 판정 셀 자체는 변경하지 않는다.
- 3개 표시 이유: MainGameBuildingGuideUiController.Configure가 MissingBoundary UI를 정확히 3개 생성하고, 코어 거리순으로 정렬된 MissingCells 중 처음 3개에 표시한다. 아트 복제 오류가 아니다.
- 위치 원인: SealSystem의 창 밖 공기 연결 탐색은 RecordWindowLeak → ResolveActionableLeakCell(firstGap: true)로 각 BFS 경로를 역추적한다. 여기서 양옆/위아래에 인정 경계가 있거나, 진행 방향의 측면 벽이 직전 칸에는 없다가 현재 칸에 처음 나타나면 해당 칸을 후보로 추가한다. 외부의 자연 지형 모서리·좁아지는 통로도 이 조건을 만족할 수 있다. 후보는 특정 방의 외곽 또는 실제 구멍임을 별도로 검증하지 않는다.
- 비인정 고체 경계도 missingBoundaryCells에 포함되므로 목록은 빈 구멍만을 의미하지 않는다. 하나의 출구에서 여러 경로가 서로 다른 후보를 잡는 것도 가능하며 HashSet은 동일 셀만 중복 제거한다.
- 좌표 표시 경로는 GetCellWorldBounds의 중심을 화면 좌표로 바꾸므로, 위 현상은 우선 누출 후보 선정 규칙의 한계로 확인된다. 제공 화면의 정확한 세 셀은 실행 중 월드 좌표를 읽지 않았으므로 확정하지 않는다.
- 이번 작업은 높이 수정과 원인 조사다. 방 외곽을 정하는 규칙 없이 후보를 임의로 삭제하면 실제 누출을 숨길 수 있어 탐색 판정은 변경하지 않았다. 향후 표시는 실제 방 출구 후보를 검증하고 출구별 중복을 묶는 방식으로 개선할 필요가 있다. 밀폐/냉각 판정과 안내 후보는 구분해야 한다.

Unity/게임 실행 및 GPU 검증 없이 코드 흐름 조사와 CPU C# 컴파일로 검증한다.

## 후속 후보 로직 수정

- 사용자 승인으로 MissingCells의 기존 경로 모서리 휴리스틱을 제거했다. 실제 밀폐 실패 영역의 공기 칸에서, 기존 건축 경계의 양 끝 사이에 빠진 칸만 찾는다. 지붕은 가로축, 차열벽/무쇠 차열벽은 세로축으로 확인한다. 양 끝의 동일 재료를 확인해 방의 맞은편 벽 사이 실내 전체를 구멍으로 오인하지 않는다.
- 중간의 비공기 칸을 통과하여 먼 경계를 찾지 않는다. 기존 비인정 고체 경계 후보도 포함해 흙/돌로 잘못 막은 칸을 진단할 수 있게 한다.
- 모든 후보를 실제 변경 없이 가상 경계로 막고 코어 창을 재탐색한다. 밀폐되지 않으면 불명확한 후보를 모두 숨긴다. 밀폐되면 코어 공간의 실제 가상 경계에 닿는 후보만 채택하고 외부의 먼 후보는 제외한다. 가상 평가에서는 후보 검증을 다시 호출하지 않아 재귀 루프가 없다.
- 실제 isSealed/leakFaceCount/sealPercent/interiorAirCells를 가상 평가 결과로 덮어쓰지 않는다. 기존 단일 대표 진단 API와 0.5타일 높이 보정은 유지한다. 화면의 최대 3칸 표시는 유효한 후보 목록에만 적용된다.
- 보수적인 안내 정책: 경계가 완전히 없거나 양 끝 재료가 다르거나 자연 지형으로만 둘러싼 개방 통로처럼 의도한 방 외곽을 확정할 수 없으면 구멍 위치를 추측하지 않는다. 이 경우 밀폐 불인정 안내는 계속 표시되며 냉각 조건도 완화되지 않는다.
- 정적 검토: 밀폐 완료는 후보 표시 없음, 외부 자연 지형 모서리는 후보 제외, 가로 지붕 틈/세로 벽 틈은 후보 수집 후 밀폐 재검사, 가상 경계에 닿지 않는 외부 후보 제외, 다른 미확정 출구가 남으면 위치 추측 중단. 실제 플레이로 이 사례들을 확인할 필요가 있다.

## 찬바람 표시 누락 후속 정정

- 위의 동일 재료 조건과 전체 밀폐 성공 조건은 실제 빠진 벽도 숨길 수 있어 폐기했다. 현재는 차열벽/무쇠 차열벽과 인정 경계(지붕·지면 등)의 세로 연결, 지붕 사이 또는 지붕과 차열벽 사이의 가로 연결을 후보로 인정한다.
- 벽 전체가 없는 경우는 지붕 끝단 바로 아래부터 인정되는 지면까지 후보로 잡는다. 지붕 끝단은 좌우 중 한쪽에만 지붕이 이어진 칸이다. 실내의 모든 세로 칸을 빠진 벽으로 오인하지 않도록 지붕 중간 아래는 제외한다. 자연 지형끼리의 틈도 제외한다.
- 가상 폐쇄 후 코어 영역에 닿는 후보를 표시하되, 다른 누출 때문에 아직 밀폐되지 않았다는 이유로 전체 후보를 삭제하지 않는다. 실제 밀폐율·냉각 판정은 변경하지 않는다.
- CPU C# 컴파일과 코드 흐름 검토만 수행하며 실제 화면의 이펙트 위치는 플레이 검증이 필요하다.

## 실내 바닥·문 위치 오표시 정정

- 이전의 '가상 경계에 닿으면 채택'은 개방 영역의 임의 칸도 통과시키는 불충분한 검증이었다. 위의 전체 밀폐 실패 시 후보 유지 정책은 폐기한다.
- 현재는 후보를 가상 수리했을 때 코어 공간이 밀폐되어야 한다. 공기 칸 후보는 수리 후 실내 경계에 닿고, 이웃 공기가 수리 전에는 코어와 연결됐지만 수리 후에는 코어 영역 밖으로 분리되는 경우만 표시한다. 단순히 실내 칸을 가상 벽으로 소비하는 경우는 제외한다.
- MainGameBuildingGuide는 열린 설치물 문의 전체 2칸 footprint를 후보 조회에 전달한다. 후보 계산에서만 문을 닫힌 경계로 가정해 문 때문에 구조적 틈의 검증이 실패하는 것을 방지한다. 전경 door/door_top은 비인정 고체 수리 후보에서도 제외한다. 문은 기존 문 안내로 다룬다.
- 지붕 끝단과 지면 사이의 후보 생성은 유지하되 위의 분리 검증을 반드시 통과해야 한다. 수리 후에도 미확정 출구가 남으면 위치를 추측하지 않는다. 실제 밀폐 캐시·밀폐율·냉각 및 문 상태는 변경하지 않는다.
- 런타임·에디터 CPU C# 컴파일과 코드 흐름 검토 범위이며 Unity 플레이/GPU 검증은 수행하지 않는다.
