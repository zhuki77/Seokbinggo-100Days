# v86 S3 보관 효과·새벽 결과 (2026-10-05)

상태: 코드 연결·CPU C# 컴파일 확인. 런타임 미검증. 밀폐 성공 서리 파동 전용 아트 미연결.

후속 확인: 2026-10-05 사용자 보고 S3 플레이 확인 완료. 에이전트가 게임을 실행한 결과는 아니다. 별도 문의로 ‘밀폐된 방 밖이지만 코어 8×10 범위 안에서 −10°C 적용’이 제기됐다. 현재 RoomTempService는 코어의 밀폐 여부로 냉각량을 정하고 범위 전체에 적용한다. v86 GDD 4-7은 −5/−10·8×10·겹침 가산을 명시하지만 동일 실내로 제한하는 조건을 명시하지 않는다. 외부 차단 의도는 추가 확정 대상이며 이번 확인에서 산식은 변경하지 않았다.

## 정본과 담당 경계

- v86 개발A `02_개발A_안내상태·월드결함.md` A3, 개발B `03_개발B_안내화면·저장·플레이.md` B3, 공통 `05_안내시스템_명세·데이터.md` S3를 직접 대조했다.
- CSV g09 주석은 ‘패널을 본 시점’이라고 요약하지만, 개발B B3는 ‘패널을 닫으면 g09 완료’를 구체적으로 요구한다. 결과 패널의 **확인**을 누르는 방식으로 연결했다. 손실만 있는 날에는 확인해도 보존 목표를 달성시키지 않는다.
- 브랜치 `feat/taeyo-ingame-interaction-polish` 유지. 기존 사용자·아트·S1/S2 변경 보존. 커밋·푸시 없음.
- A 영역: `RoomTempService`, `StorageTemperatureService`, `MainGameGoalTracker`. B 연동 영역: `MainGameCraftingUiController`, `MainGameGoalUiController`, `SaveGame`. 병합 시 B의 창 표시·저장 필드 수정과 충돌 여부를 확인해야 한다.

## 변경

| 장독 창 | 현재 온도·요구 온도, 온도 막대의 기준선과 현재 위치. 막대는 표시 전용이며 온도 산식을 바꾸지 않는다. 자연 상자에는 표시하지 않는다. |
| 미달 안내 | 얼음은 CSV `storage_below`. 음식만 있으면 얼음 문구를 쓰지 않고 현재/요구 숫자를 표시한다. |
| 충족 전환 | 미충족→충족마다 이벤트 1회, 얼음은 `storage_ok` 2초. 이후 ❄와 온도 숫자. 로드 시 기준선만 설정해 성공을 재생하지 않는다. |
| 새벽 결과 | 용기별 얼음 처리 전→후, 안전 보존 개수, 실제 손실 개수, 당시 온도 기록. 자연 새벽·휴식의 기존 일일 처리 경로에 연결. |

## 저장·복원 검토

- 스키마 28→29. 용기별 결과와 미확인 새벽 목록을 저장한다. 이미 확인한 g09는 기존 목표 완료 이력으로 보존한다.
- 이전 스키마의 `pendingDawnDay`/`pendingDawnKeptIce`는 용기 세부정보 없는 합계 패널로 이관한다. 아직 확인하지 않은 여러 새벽은 덮어쓰지 않는다.
- 캡처는 결과 목록을 깊은 복사한다. 복원은 기존 복원 중단 구간 이후에 수행하며 일일 처리를 다시 실행하지 않는다.
- 새 피드백 기록의 잘못된 수량·비유한 온도/좌표는 정규화 단계에서 제거한다. 기존 월드 복원 판정을 강화하거나 완화하지 않는다. 상자 좌표의 엄격 검증 시작 버전은 기존 **28**을 유지했다.
- 확인 후 변경은 다음 실제 저장에 반영된다. 확인 이전에 생성한 저장 파일을 그대로 로드하면 미확인 패널이 다시 나오는 것은 그 저장 시점의 상태다.

## 검증과 제한

- 런타임과 에디터 C# 프로젝트를 **순차** CPU 컴파일: 오류 0개. 런타임 경고 3개, 에디터 경고 38개는 기존 사용 중단 API·미할당 필드 경고다.
- 정적 검토: 혼합 요구 온도, 미달→충족 전환, 소수 손실, 원인 순서, 손실만 있는 결과, 확인 전 목표 미완료, 일일 처리→새벽 자동 저장 순서, 구버전 결과 이관·깊은 복사·복원 중 이벤트 억제.
- Unity/게임/플레이 모드·GPU 검증은 수행하지 않았다. 새벽 결과 패널의 가독성, ❄ 글리프, 막대의 실제 겹침, 저장 후 이어하기는 실제 플레이 미검증이다.
- 이 턴에 Unity MCP 호출 도구가 노출되지 않았다. 서버 중단이나 Unity 세션 비활성으로 단정하지 않는다.
- 밀폐 성공의 **코어 주변 서리 파동 3~4프레임**은 원본 연결이 없다. 다른 아이템 그림·임의 생성 아트로 대체하지 않았다. 아트 담당자가 전용 원본을 확인한 뒤 연결해야 한다.

## 사용자 플레이 확인 순서

1. 냉기 범위 안의 장독에 얼음 조각을 충분히 넣고 문을 열어 현재 온도가 요구 기준보다 높은 상황을 만든다. 미달 문구와 막대를 확인한다. 이미 자연 온도로 기준을 충족하면 이 조건 시험이 되지 않는다.
2. 문을 닫아 실제 온도가 기준 이하로 내려가는지 확인한다. 성공 문구는 전환 시 한 번, 이후 ❄와 현재/요구 숫자로 바뀌어야 한다. 음식과 얼음을 섞어도 얼음 기준이어야 한다.
3. 자연 새벽 또는 따뜻한 별도 침실의 보금자리로 밤을 넘긴다. 처리 전→후 수량과 안전 보존 개수가 실제 장독과 맞아야 한다. g09는 패널의 확인 전에 자동 완료되면 안 된다.
4. 확인을 눌러 안전 보존 결과를 닫는다. g09가 완료되고 첫 석빙고 사슬이 끝나면 P1 목표 선택으로 넘어가야 한다.
5. 문을 열어 미달 상태로 다음 새벽을 넘긴다. 기존 정수 손실이 발생할 만큼 얼음을 넣어 둔다. 실제 손실과 ‘밀폐가 열려 있었어요. 문·벽을 점검하세요.’가 맞는지 확인한다. 1개만 넣으면 소수 누적으로 첫날 정수 손실이 없을 수 있다.
6. 밀폐된 별도 방의 냉기 범위 밖 장독, 침공 열기가 남은 밀폐·범위 안 장독을 각각 확인한다. 여러 원인이 있으면 밀폐→범위→열기 순서다.
7. 여러 장독에서 이전/다음으로 모든 용기를 확인하고 글자가 버튼을 덮지 않는지 확인한다. 메뉴를 열었다 닫아도 결과가 사라지면 안 된다.
8. 패널 확인 전에 저장→타이틀→이어하기: 동일 결과와 미완료 g09가 유지되어야 한다. 확인 후 다시 저장→이어하기: 이미 소비한 패널이 재등장하면 안 된다. 이미 안전한 저장을 로드했다고 성공 문구가 재생되면 안 된다.
