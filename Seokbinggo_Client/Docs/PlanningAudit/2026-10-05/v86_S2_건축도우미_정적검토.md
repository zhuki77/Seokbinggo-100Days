| 빠진 경계 상태 | 인정되지 않는 고체 경계와 누출 경로의 첫 경계 틈 후보를 모아 코어 거리순으로 정렬한다. 창 끝 좌표를 곧바로 수리 지점으로 표시하지 않는다. |
| 수리 상태 | 이전 후보 중 실제 밀폐 경계로 바뀐 칸, 실제 닫힌 열린 문에 대해 `Repaired`를 발행한다. 목록에서 사라졌다는 이유만으로 수리 처리하지 않는다. |
| 밀폐 성공 | 같은 코어의 미밀폐→밀폐 변화 또는 정상 플레이 중 첫 코어를 밀폐된 방에 설치했을 때 `core_sealed_now`를 한 번 발행하고 `seal_success`를 짧게 표시한다. |

행동 안내 4개(`placed_block_not_seal`, `door_open`, `core_unsealed`, `seal_success`)는 기존 CSV에서만 읽는다. 버튼명 **예시 윤곽**은 S2 명세의 조작 요소 용어이며 새로운 행동 안내 문장을 추가한 것이 아니다.

## 저장·복원·성능 검토

- S2는 세이브 필드를 추가하거나 스키마 28을 변경하지 않는다. 월드·문 상태를 직접 수정하지 않는다.
- S1 복원 중 `IsSuspended`를 확인하며, 복원 버전·SealSystem 변경 직후에는 상태 기준선만 설정한다. 이미 밀폐된 저장을 불러왔다는 이유로 수리/성공 연출을 반복하지 않는다.
- 가까운 코어가 바뀌면 다른 방의 수리 목록을 비교하지 않고 성공 이벤트를 억제한다. 최초 코어를 정상 설치한 경우는 별도로 처리한다.
- 기존 단일 누출 좌표 API와 실제 밀폐/누출면/밀폐율 산식을 유지한다. 새 후보 목록을 기존 침공 손상 칸으로 사용하지 않는다.
- 상태 확인은 0.2초 간격이다. 타일/문/설치물 변경으로 무효화된 판정 또는 코어 변경 때만 진단을 재계산한다. 전체 월드를 매 프레임 스캔하지 않는다.
- 누출 경로는 기존 제한된 창의 부모 경로를 사용한다. 넓은 개방 공간처럼 방 테두리를 특정할 수 없으면 임의의 먼 칸을 정답으로 만들지 않는다. 복잡한 동굴에서 후보의 적절성은 수동 플레이 검토가 필요하다.
- 메뉴·사망·전환·일시정지에는 표시를 숨기며 토글 버튼 클릭이 채굴 입력으로 이어지지 않도록 HUD 입력 차단에 연결했다.
- S4 위험/전투/건축/목표 통합 우선순위 엔진은 별도 단계다. 현재는 건축 반응과 S1 힌트의 연결만 추가했다.

## 사용자가 플레이로 확인할 순서

1. 코어를 설치하고 우측 상단 **예시 윤곽 · 6×2** 버튼으로 켜기/끄기. g05가 이미 완료된 세이브에서는 기본 꺼짐이다.
2. 흙·돌이 설치 가능한 위치에서는 노랑과 불인정 안내, 차열벽·지붕·닫힌 문 배치에서는 유효 위치에 초록. 설치 불가능한 위치에서는 재료에 관계없이 빨강이어야 한다.
3. 예시를 참고해 방을 만들고 문 닫기 → 밀폐 성공 안내 한 번, g05 완료와 윤곽 자동 끄기.
4. 다른 구멍 없는 방에서 문 열기 → 문 테두리 깜빡임과 닫기 안내. 닫기 → 테두리 사라짐, 성공 한 번.
5. 경계 한 칸 제거/복구 → 상태 갱신. **현재 구멍·수리 전용 그림은 원본 연결 전이라 보이지 않는 것이 예상 상태다.**
6. 밀폐 상태 저장→타이틀→이어하기 → 이미 밀폐됐다는 이유로 성공 안내 반복 없음. 토글 클릭 시 채굴/공격 없음.

## 후속 수정 — 일반 설치물의 잘못된 빨간 미리보기

사용자가 용광로를 설치할 수 있는데도 빨간색으로 표시되는 현상을 보고했다. 원인은 최초 S2 연결에서 `placementValid && IsSealElement`를 모든 설치물에 적용한 것이다. 밀폐 벽이 아닌 제작대·화로·용광로·대장간·얼음 모루·저장고·장독·보금자리·까치 둥지·포탑·냉각 장치·꾸미기 등에 같은 조건이 적용될 수 있었다. 전경 팔레트에서는 밀폐에 참여하지 않는 벽지도 영향을 받았다.

- 설치물 경로: 실제 `placementValid`만 미리보기·범위 표시 색에 사용한다.
- 전경 팔레트: 실제 설치 가능 여부를 기본으로 사용하고 흙·돌 계열에만 `HasNonSealTerrainWarning`으로 빨간 경고를 더한다.
- 건축 안내와 상태 값도 같은 흙·돌 경고 함수를 사용한다. 불인정 설치물 전체를 위험 재료로 취급하지 않는다.
- 밀폐 산식·화이트리스트·실제 설치 가능 여부는 변경하지 않았다.
- 사용자가 참고한 이전 설명의 **'저장고·장독·제작대는 빨강'은 잘못된 안내이며 철회**한다. 일반 설치물은 유효 위치에서 초록이 맞다.
- 정적 코드 검색으로 두 배치 색 경로를 확인했다. 런타임·에디터 CPU C# 컴파일을 순차 수행해 오류 0개를 확인했다. 최초 런타임 빌드는 `project.assets.json` 부재로 실패했으며 정상 빌드로 복원한 뒤 `--no-restore` 재확인에 성공했다.
- 이번 도구 목록에는 Unity MCP 호출 도구가 노출되지 않아 추가 MCP 확인은 하지 못했다. 이를 서버 종료나 Unity 세션 비활성화로 단정하지 않는다. 실제 미리보기 색은 런타임 미검증이다.

### 기획자 컨펌 — 밀폐 경고 노랑

사용자가 전달한 기획자 컨펌을 기존 v86 빨강 지정보다 우선 적용했다. 설치 불가능 = 빨강, 설치 가능하지만 흙·돌 밀폐 불인정 = 노랑, 나머지 설치 가능 = 초록으로 구분한다. 안내 문구와 실제 설치·밀폐 판정은 유지한다. 위 후속 수정의 빨간 경고 설명은 변경 당시 기록이며 현재 경고색은 노랑이다.
