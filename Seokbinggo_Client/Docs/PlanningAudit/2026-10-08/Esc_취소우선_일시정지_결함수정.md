# Esc 취소 우선 처리

## 원인

일시정지 컨트롤러는 Update 순서 −55, 전경 설치 팔레트와 제작 UI는 −50이다. 같은 프레임에서 일시정지 여부를 먼저 확인하므로, 설치 취소가 Esc 사용 표시를 남기기 전에 일시정지가 열렸다. 스크립트 실행 순서에 의존하던 방어 조건이 원인이다.

## 수정

- 일시정지 등 셸의 Esc 처리를 기존 LateUpdate의 마지막 판단 단계로 이동했다. 취소 처리는 각 Update에서 먼저 완료한다.
- GameplayInput.TryConsumeEscape로 프레임당 Esc 처리 하나만 허용한다.
- 전경·시설 설치 취소, 제작/인벤토리/소환 확인창 닫기, 기존 도감, 디버그 도움말·보스 선택창, 오프닝 건너뛰기에 같은 소비 규칙을 적용했다.
- 처리할 취소 동작이 없으면 셸에서 Esc를 소비하고 일시정지를 연다. 일시정지 재개·설정 닫기·결과 계속 플레이·휴식 확인 취소의 기존 셸 동작은 유지한다.
- 기존 LateUpdate의 보스 격파 결과 표시 흐름은 유지했다.

## 직접 플레이 확인

1. 흙 또는 차열벽 설치 미리보기를 켜고 Esc를 한 번 누른다. 미리보기만 사라지고 일시정지가 열리지 않아야 한다. 재료도 유지된다.
2. 다시 Esc를 누르면 일시정지가 열린다. 다음 Esc는 일시정지를 닫는다.
3. 화로·얼음 저장고 등 시설 설치 미리보기에서도 같은 순서로 확인한다.
4. 인벤토리·제작·장비·도감 창을 각각 열고 Esc를 누른다. 해당 창만 닫혀야 한다. 다음 Esc는 일시정지를 연다.
5. 소환 확인창에서 Esc를 누른다. 확인창만 닫히고 인벤토리는 남는다. 다음 Esc는 인벤토리만 닫으며, 그 다음 Esc는 일시정지를 연다.
6. 디버그 도움말(F5)과 보스 선택창을 쓰는 경우 Esc로 닫아도 일시정지가 같이 열리지 않아야 한다.
7. Esc를 길게 눌러도 취소 후 일시정지까지 연속 처리되지 않아야 한다. 키를 떼고 다시 누를 때 다음 동작이 실행된다.

## 검증

- CPU 런타임 C# 컴파일: 오류 0, 경고 3.
- CPU 에디터 C# 컴파일: 오류 0, 경고 38.
- 정적 검토: 셸 Update에서 일시정지를 열지 않고, LateUpdate에서만 남은 Esc를 처리함을 확인. 관련 취소 경로가 공통 Esc 소비를 사용하는지 확인.
- 회귀 테스트에 실행 순서·공통 소비 배선 확인을 추가했다. Play Mode 및 런타임 테스트는 실행하지 않았다.
