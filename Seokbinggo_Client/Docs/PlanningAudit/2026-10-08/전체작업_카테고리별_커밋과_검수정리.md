# v86 게임플레이 개선 전체 변경 정리

기준 커밋: `d158eff7bad5b753a289bcfdb301f85917181882` (`main`과 동일).

## 기능별 결과

### 인벤토리·창고·장비
- 인벤토리/장독창고/퀵슬롯 클릭 앤 드롭: 좌클릭 전체, 빈손 우클릭 절반(올림), 보유 중 우클릭 1개 놓기.
- 창고 Shift+좌클릭 전체, Shift+우클릭 절반 즉시 이동. 보관 상태가 다른 같은 ID는 합치지 않음.
- 손에 든 스택과 원래 보관함/슬롯 저장. ESC는 먼저 원위치 반환, 빈손 ESC는 창 닫기. 창고 닫기에도 반환.
- 인벤토리 WASD 선택 제거. 퀵슬롯에서 집은 상태에도 이동·점프·밧줄 조작 유지.
- 무기 개수 표시 제거, 원거리 무기 탄약 표시 및 글꼴 통일, 무기 MaxStack=1 유지, 모든 아이템 퀵슬롯 보관 허용.
- 장비 보유와 인벤토리 통합, 장착/해제 시 수량 보존, 장착 중 창고 이동 거부. 구 저장의 별도 장비 보유를 1회 이전.
- 장독창고 내용물이 있어도 철거 허용, 내용물의 수량·보관 상태를 드랍/회수/저장에 보존.

### 제작·목표·진행 안내
- 제작대별 진행 1개+대기 4개, 제작/제련 큐 표시·취소·재료 환급·저장, 큐 간 독립 진행.
- 상호작용 거리 안에서만 퀵슬롯 위 제작 진행바 표시, 직접적인 초 표시 제거.
- v86 S1~S8 목표·가이드·밀폐·보관·성장/결과 화면 연결과 데이터 임포트.
- 제작 목표는 부족 재료/가공 재료 원료·연료를 안내하고 준비 완료 시 해당 제작대를 안내.
- 보스 결과와 석빙고 완성/철거 후 상태, 목표/거점 화살표의 좌표·문구, 침공 다음 낮의 복구 안내 주기 보완.
- 상단 아이템 ID 노출을 표시 이름으로 변경, ESC 취소 우선순위 적용, B 레시피 숨김 정책.

### 요괴·침공·전투
- 일반 밤/정규 침공의 코어 선정 거리 구분과 코어 순차 목표, 재봉쇄 시 벽 파괴 재개, 몹 체격에 맞는 통로 확보.
- 코어 도달·열기 잔량 적용 후 다음 코어 또는 랜덤 서성거림 전환, 인식 범위 내 플레이어 추적.
- 야광귀 코어 도달 후 절도 목표 전환, 실제 절도 성공 확인, 도주 및 훔친 아이템 회수 보완.
- 시간 배속/밤 전환의 침공·백중날 처리, 보스 위치/표시·장애물 대응 보완.
- 장비 Q 스왑으로 공격 딜레이를 초기화하는 결함 수정, 피격 알람 최소 유지 시간.

### 월드·물리·밀폐·온도
- 캣닢 지하 생성은 동굴 조건 적용. 플레이어/요괴 지형 끝 충돌 및 얼음 이동 가속·감속 개선.
- 드랍템은 실제 충돌이 있는 경우 가까운 빈 공간으로 탈출, 배경 타일에는 탈출하지 않음.
- 설치물 중복 설치·철거, 문/누출 위치와 찬바람·복구 체크, 밀폐 성공 서리 파동 위치·크기 개선.
- 저장된 회복 대기 시간 유지, 보금자리 리스폰/시간 되돌리기 제한, 빙정 냉각로·장독창고 보관 온도 연결.
- 설한풍 투구/갑옷/신발 3종의 햇빛 피해 면역 추가. 기존 내한 조건과 세트 화염/체온 감소 유지.

### 아트·씬·검수 자료
- 누적 납품 스프라이트/임포트 설정/카탈로그·타일 연결, 요괴 정렬 순서, 무기 공격 모션 위치 보정.
- 객귀 보스 체력 프레임과 계속 플레이 버튼 아트, 밀폐 서리 파동, 신기전/채찍선 공격 아트 반영.
- MainGame 씬과 생성 도구 배선, 회귀 점검 코드, 아트 원본 대조·시각 자료 및 기능별 수동 검수 기록 포함.

## 검증 및 남은 확인

- Runtime 및 Editor C# 프로젝트 CPU 컴파일: 오류 0개.
- C#/Editor 소스 `git diff --check`: 공백 오류 없음. Unity 자동 생성 메타데이터의 직렬화 공백은 유지.
- 회귀 코드를 추가/수정했으나 실행하지 않음. Unity/게임 실행·Play Mode·GPU·Windows 플레이어 빌드 검증은 수행하지 않음.
- 사용자가 S5~S8 플레이 확인을 완료했다고 보고한 이력이 있으나, 그 이후 인벤토리·장비·제작 대기열·설한풍 면역 등 추가 변경은 각 문서의 플레이 항목을 재확인해야 함.
- 오프닝 일러스트 3장은 아직 미제공이며 연결 구조만 준비됨.
- MCP 콘솔에는 기존 `guideDay 0 -> 1` 저장 왕복 불일치 및 플레이어/장비 UI NullReferenceException 로그가 관측됨. 이 PR의 CPU 컴파일 통과를 해당 실행 결함의 해소 증거로 해석하지 않음.
- 기존 기술 ID `imugi_boss`/`BossKind.Imugi`를 강철이(30일 보스)에, `gangcheol`/`YokaiKind.Gangcheori`를 이무기(심층 상주)에 계속 사용하며 저장 ID 마이그레이션은 하지 않음.
