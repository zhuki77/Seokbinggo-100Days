# 제작대별 제작 대기열

2026-10-08 사용자 요청. 용량은 사용자 확정에 따라 **진행 1개 + 대기 4개**다. 기존 v86 단일 제작/설비 종류별 제련 모델에 대한 후속 변경이다.

## 구현

- 설치물의 `objectId`마다 독립 대기열을 갖는다. 작업대·화로·용광로·얼음 모루·대장간을 지원한다. 손 제작은 별도 대기열을 쓴다.
- 화로/용광로의 일반 제작과 제련은 같은 설치물의 대기열에서 선착순으로 진행한다. 여러 설치물은 동시에 진행한다.
- 예약할 때 재료와 제련 연료를 미리 확보한다. 재료 부족/대기열 초과 시 재료를 소비하지 않는다.
- 제작 화면 아래쪽에 현재 작업과 남은 시간, 대기 4칸, 각 작업 취소 버튼, 회수 버튼을 표시한다. 상세 설명은 기존 스크롤을 유지하면서 높이를 줄였다.
- 진행/대기 작업 모두 취소할 수 있다. 해당 작업 재료를 반환하고 진행 작업 취소 시 다음 작업을 처음부터 시작한다. 이미 완료한 작업은 취소되지 않는다.
- 반환 시 인벤토리가 가득 차면 회수 대기분에 보관한다. 화면의 회수 버튼으로 받을 수 있고 저장에도 포함한다. 취소 때문에 재료를 버리거나 없애지 않는다.
- 일반 제작 완료품은 기존처럼 자동 지급을 시도하고, 공간 부족 시 회수 대기분에 보관한다. 제련 완료품은 회수 버튼으로 받는다.
- 제련은 기존 빙결 온도 규칙을 유지한다. 제련 작업에서 멈추면 뒤의 작업도 순서를 건너뛰지 않는다.
- 제작대 철거/파괴 시 남은 작업을 취소·반환한다. 공간 부족분은 보존하고 이후 게임 틱에서 지급을 재시도한다. 새로 설치한 같은 종류의 제작대는 다른 ID이므로 이전 대기열을 상속하지 않는다.
- 저장은 `stationProduction`에 설치물 ID, 종류, 위치, 작업 순서, 적용된 제작 시간과 남은 시간, 예약 재료 상태, 회수 대기분을 기록한다. 기존 저장의 이 필드 누락은 빈 목록으로 처리한다.
- 구 저장의 전역 제작/종류별 제련은 기존 서비스에서 계속 진행할 수 있다. 아직 끝나지 않은 작업·미회수 제련품은 처음 연 같은 종류의 제작대에 귀속시킨다. 구 저장에는 설치물 ID가 없어서 원래 설치물을 특정할 수 없다. 재료를 다시 차감하지 않는다.
- 후속 사용자 요청: 퀵슬롯 위 HUD 진행바는 해당 제작대의 상호작용 거리 안에서만 표시한다. 범위 안에 여러 진행 중 제작대가 있으면 가장 가까운 곳을 표시한다. 초/느낌표 문구는 숨기고 기존 파란 진행바만 유지한다. 거리 밖에서도 제작 자체는 계속 진행한다.

## 직접 플레이 확인

1. 작업대에서 제작을 다섯 번 예약한다. 진행 1개·대기 4개가 표시되고 여섯 번째는 재료 차감 없이 거부되는지 본다.
2. 같은 종류 작업대 두 개를 설치해 각각 예약한다. 각 화면의 작업 목록이 분리되고 동시에 시간이 줄어드는지 본다. 한쪽을 취소해도 다른 쪽이 유지되어야 한다.
3. 다른 제작법을 섞어 예약하고 대기 중간 항목을 취소한다. 해당 작업의 재료만 반환되고 나머지 순서가 유지되어야 한다.
4. 진행 중 항목을 취소한다. 이미 경과한 시간과 무관하게 재료가 반환되고 다음 항목이 자신의 전체 제작 시간으로 시작해야 한다. 취소 버튼을 빠르게 여러 번 눌러도 재료가 중복 반환되지 않아야 한다.
5. 화로에서 제련과 일반 제작을 섞어 예약한다. 같은 대기열에 표시되고 앞에서부터 하나씩 완료되어야 한다. 제련 취소 시 투입 재료와 연료가 모두 반환되어야 한다.
6. 제련 중 빙결 온도로 만든다. 남은 시간과 다음 대기 항목이 정지하고 온도가 회복되면 이어서 진행해야 한다.
7. 예약 후 빈 인벤토리를 다른 아이템으로 가득 채우고 취소한다. 작업은 제거되고 회수 대기 수가 남아야 한다. 공간을 확보한 뒤 회수하면 재료를 받아야 한다.
8. 진행/대기/미회수 완료품/미회수 반환 재료가 있는 상태로 저장→타이틀→이어하기한다. 제작대별 순서와 남은 시간, 미회수분이 유지되고 재료가 다시 차감되지 않아야 한다.
9. 예약 중인 제작대를 철거하거나 요괴가 파괴하도록 한다. 예약이 취소되고 재료가 반환되어야 한다. 인벤토리가 가득 찼다면 공간 확보 후 반환분이 지급되어야 한다. 같은 위치에 다시 설치한 제작대는 빈 대기열이어야 한다.
10. 완료 직전 취소 버튼을 누른다. 이미 완료된 작업 때문에 다음 작업까지 잘못 취소되거나 완료품과 취소 재료를 동시에 받는 일이 없어야 한다.
11. 제작 진행 중 제작대의 상호작용 거리 밖으로 나가면 퀵슬롯 위 진행바가 숨겨지고, 다시 접근하면 현재 진행률로 표시되어야 한다. 숫자 초/느낌표는 표시되지 않아야 한다.

## 검증 범위

- CPU C# 컴파일: 게임/에디터 프로젝트 모두 오류 0개. 기존 경고는 각각 3개/38개.
- 정적 흐름 검토: 설치물 ID 배선, 예약 재료 원자적 차감, 취소·회수, 다음 작업 전환, 온도 정지, 철거 반환, 저장·복원 연결.
- 대기열 용량/독립성/취소 반환/저장 타이머/깊은 복사/철거/인벤토리 가득 참 회귀 시나리오를 에디터 테스트 코드에 추가했다. 실행하지 않았다.
- Unity MCP 콘솔 읽기만 수행했다. Unity/게임/Play Mode, 런타임 서비스 실행, GPU 검증은 하지 않았다.
- 콘솔에 남은 `guideDay` 0→1 저장 왕복 검증 오류는 기존 별도 확인 항목이며 이번 대기열 검증 성공의 근거로 사용하지 않았다.
