# 장독창고 내용물 파괴 드랍

2026-10-08 사용자 요청: 내용물이 있는 장독창고도 부술 수 있고, 창고와 내용물이 함께 바닥에 떨어진다.

- 플레이어의 설치물 채굴/회수 공통 경로에서 내용물 유무에 따른 차단을 제거했다.
- 설치물을 실제로 제거한 뒤 보관 기록에서 내용물을 한 번만 꺼내고 기록을 삭제한다. 열린 창고 화면이 잡고 있던 이전 인벤토리 참조도 비운다.
- 창고 1개와 각 슬롯 묶음을 서로 다른 방향으로 드랍한다. 대량 묶음의 개수만큼 물리 오브젝트를 생성하지 않고, 슬롯 묶음별로 드랍 1개를 만든다.
- 각 묶음의 아이템 ID·개수·보관 상태·용해 잔여량을 드랍에 보존한다. 플레이어/까치 줍기와 월드 드랍 저장·복원도 같은 상태를 유지한다.
- 빈 창고도 기존처럼 창고 아이템 1개를 드랍한다. 반복 제거 요청은 설치물 제거 단계에서 실패하므로 같은 내용물이 두 번 드랍되지 않는다.
- 요괴의 공격 대상/설치물 내구도 범위는 이번 요청에서 확장하지 않았다.

## 플레이 확인

1. 창고에 돌·나무·얼음을 서로 다른 슬롯에 넣고 좌클릭을 유지해 부순다. 창고와 각 묶음이 바닥에 흩어지고 모두 주웠을 때 개수가 맞아야 한다.
2. 같은 아이템을 여러 슬롯에 넣은 경우도 총개수를 확인한다. 무기는 각각 1개짜리 드랍이어야 한다.
3. 소지품이 가득 찬 상태에서 부순다. 못 주운 드랍이 바닥에 남아 있어야 한다. 저장→타이틀→이어하기 후에도 창고는 없어지고 드랍은 같은 개수로 남아야 한다.
4. 일부 상태가 저하된 보관품을 넣어 부수고 다시 줍는다. 보관 상태가 새것으로 초기화되지 않아야 한다.
5. 빈 창고 파괴와 파괴 직후 반복 입력을 확인한다. 창고 아이템이나 내용물이 중복 지급되지 않아야 한다.

## 검증

- CPU C# 컴파일로 게임/에디터 문법·참조 확인. 런타임 동작은 코드 흐름으로 검토한다.
- 창고 내용물 추출·기록 제거·상태 보존·중복 추출 방지 회귀 시나리오를 기존 테스트 코드에 추가했다. 실행하지 않았다.
- Unity/게임/Play Mode 실행 및 GPU 검증은 하지 않는다.
