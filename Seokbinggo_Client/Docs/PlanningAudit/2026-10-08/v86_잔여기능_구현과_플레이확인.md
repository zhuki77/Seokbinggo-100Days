# v86 잔여 기능 구현 및 직접 플레이 확인

기준: `냥빙고_30일완성_v86_20261003.zip` 개발 A A9/A10, 개발 B B12/B13. 30일 보스 명칭은 사용자 확정에 따라 강철이이며 기존 기술 ID `imugi_boss`/`BossKind.Imugi`는 유지한다. 사용자가 S1~S8 플레이 확인을 완료한 상태에서 진행했다.

- 사용자가 위 플레이 확인사항 완료 및 B6/B10 기검증을 확인했다. S1~S8 완료 상태도 유지한다.

- 남은 v86 검수: B0 새 게임부터 30일 강철이 격파·계속 플레이까지 연속 플레이(저장→타이틀→이어하기 3회 포함), B14 기획서 미독자 5명 테스트, B15 제출 Windows 실행 파일 검증.
- 검수 외 잔여 작업: B12 오프닝 일러 3장 조달·등록 및 실제 화면 확인. 현재 연결 구조만 완료했다.
- 별도 확인 필요: 얼음 이동 수정 확인 중 Unity 콘솔에 `MainGamePlayerController.Update`의 `wireSnare.Tick` NullReferenceException 기록 2건이 관측됐다. 원인과 재현 여부는 아직 확인하지 않았으므로 해결 완료로 간주하지 않는다.

## 1. 기존 저장 호환부터 확인

1. 기존 저장을 이어한다. 보금자리·저장고·화로·문·차열벽이 기존 위치에 있고, 플레이어 위치와 인벤토리 수량이 유지되는지 본다.
2. 지상 얼음 호수를 찾는다. 기존 저장은 건축물·굴착/설치 이력·벽지 이력·플레이어·드랍템·눈물 보따리가 있는 지대를 피해서 호수를 추가한다. 지하 제단과 그 주변 호수는 유지한다.
3. 저장 → 타이틀 → 이어하기를 두 번 반복한다. 지상 호수 위치가 옮겨지거나 계속 추가되면 결함이다.
4. 지상 호수 얼음 한 칸을 채굴하고 저장 → 이어하기 한다. 그 칸이 다시 채워지지 않아야 한다. 기존 건축물·채굴 결과도 유지되어야 한다.

호수 위치·가로/세로는 저장의 `hasSurfaceIceLakeArena`, `surfaceIceLakeOrigin`, `surfaceIceLakeWidth`, `surfaceIceLakeHeight`에 기록한다. 기존 자원 생성 버전과 확정 시드, 지하 제단 생성 규칙은 변경하지 않는다. 새 호수 폭 기본값 32칸은 구현 기본값이며 기획 확정 수치로 주장하지 않는다. `WorldGenerationConfig`의 Surface Ice Lake Arena Width에서 조정할 수 있다. 높이는 기존 Ice Lake Height를 사용한다.

## 2. 강철이 등장과 아레나

준비: 30일차 낮 저장이 편하다. 먼저 배속 1에서 확인한다. 낮 저장을 다시 불러오면 밤 등장 전 상태부터 재확인할 수 있다. 보스 전투 중 저장 제한은 유지된다.

1. 30일 낮의 보스 예고에서 강철이 등장 장소가 얼음 호수로 표시되는지 본다.
2. 강철이 격파 목표가 활성화되어 목표 화살표가 표시되면 지상 호수를 가리키는지 본다. 지하 제단 옆 호수를 가리키면 결함이다.
3. 밤 시작 때 지하 또는 기지에서 기다린다. 강철이가 플레이어 주변에 나타나거나 지하로 쫓아오면 결함이다. 보스 체력바만 보이는 것은 전역 보스 상태 표시이므로 실제 위치는 지상 호수에서 확인한다.
4. 지상 호수로 이동한다. 강철이가 호수에 있고, 접근하면 정상적으로 이동·접촉 공격·특수 공격을 해야 한다.
5. 호수 바깥으로 빠져나오거나 호수 아래의 지하로 내려간다. 강철이가 그쪽으로 계속 추격하지 않아야 한다. 다시 호수에 들어가면 전투가 이어져야 한다.
6. 가능하면 낮 저장을 다시 불러와 호수 표면 일부를 채굴한 뒤 밤을 맞는다. 비행형 강철이는 호수 위 빈 공간 후보도 사용하므로 표면을 채굴했다는 이유만으로 등장이 없어지면 결함이다. 아레나 전체를 천장까지 설치물로 막은 상황은 정상적인 빈 공간 검증과 구분한다.
7. 격파 보상·결과 화면·계속 플레이가 기존처럼 이어지는지 확인한다.

## 3. 냉기 장치 실온 합산

빙정 냉각로와 이번 냉기 장치(`cold_device`)는 다른 기능이다. 냉각로의 얼음 용해 보호를 이 시험으로 대체하지 않는다.

준비: 같은 방 안에 얼음 저장고 코어와 냉기 장치를 1~2칸 정도 떨어뜨려 설치할 수 있게 한다. 장치와 코어의 냉각 범위가 겹치는 같은 칸에서 측정한다. 화면 우측 상단의 **실온**을 비교하며, 플레이어 **체온**이 즉시 같은 값으로 변하는 것을 기대하지 않는다. 침공 열기 잔량이 없는 때 비교하면 편하다.

1. 문을 닫아 밀폐한 뒤, 코어만 있을 때 실온 A를 적는다.
2. 냉기 장치를 하나 설치하고 같은 칸에서 실온을 본다. **A보다 정확히 10°C 낮아져야 한다.** 예: 자연 실온 0°C, 코어 하나 −10°C → 장치 추가 후 −20°C.
3. 장치를 철거한다. 같은 칸의 실온이 A로 돌아와야 한다. 설치·철거를 반복해 냉각량이 누적되거나 남지 않는지 본다.
4. 장치를 다시 설치하고 문을 열어 비밀폐로 만든다. 자연 실온 0°C이고 두 범위가 겹친다면 코어 −5 + 장치 −5 = **−10°C**가 기준이다. 밀폐 때의 −20°C가 그대로 남으면 결함이다.
5. 문을 다시 닫는다. 두 냉기원의 밀폐 냉각이 복귀해야 한다.
6. 밀폐된 옆방 또는 벽 밖으로 나간다. 장치가 있는 방의 냉기가 벽을 넘어 적용되면 결함이다. 단순 거리만 가까운 것으로 적용되면 안 된다.
7. 범위 겹침 안쪽에 장독 창고를 놓고 E로 연다. 표시되는 보관함 실온도 장치의 냉각을 포함해야 한다. 바깥 보관함에는 적용되지 않아야 한다.
8. 장치를 둔 채 저장 → 타이틀 → 이어하기 한다. 동일 위치 실온과 보관함 상태가 유지되어야 한다.

냉기 장치는 코어와 같은 범위 8×10칸을 사용한다(현재 전역 데이터). 장치를 실제 요괴 목표 코어로 추가하거나, 장치만으로 얼음 저장고 설치 목표를 완료시키지는 않는다. 침공 열기는 기존 실제 코어 적용 경로를 유지하며 장치 수만큼 중복 가산하지 않는다.

## 4. 조작 통일 — 이 순서로 확인

| 상황 | 입력 | 정상 결과 |
|---|---|---|
| 작업대·화로·장독·보금자리·단열 문 근처 | 대상을 조준하고 E | 해당 시설 열기/사용/문 개폐 |
| 캣닢·상자 근처 | 대상을 조준하고 E | 채집/상자 열기 |
| 소모품을 핫바에서 선택 | 우클릭 | 선택한 소모품 사용 |
| 블록·벽지·문·시설 설치 미리보기 | 우클릭 | 유효한 위치에 설치 |
| 설치 미리보기 | Esc | 설치 취소, 재료 보존 |
| 공격/채굴, 설치 미리보기 없음 | 좌클릭 유지 | 기존 공격/채굴 |
| 부채 능력 | F | 기존 부채 능력 |
| 벽지 제거 | Shift+우클릭 | 기존 벽지 제거 |

상세 확인:

1. **E가 아이템을 먹지 않는지:** 회복 버섯 또는 얼음 조각을 선택한 채 문을 조준하고 E를 누른다. 문만 열리고 선택 아이템 수량은 그대로여야 한다.
2. **목표 선택:** 문·화로·상자 등이 가까이 있는 곳에서 조준을 바꾸며 E를 누른다. 플레이어 상호작용 범위 안에서 조준에 가까운 대상을 사용해야 한다. 멀리 조준했다고 먼 시설을 열면 결함이다.
3. **우클릭 소모품:** HP가 줄었을 때 버섯/캣닢, 체온이 오른 때 얼음 조각, 사용 가능한 부적을 각각 선택해 우클릭한다. 한 번에 하나만 소모되고 효과가 적용되어야 한다. 얼음 조각에는 블록 설치 미리보기가 나오지 않아야 한다.
4. **인벤토리에서도 확인:** Tab → 소모품 선택 → 우클릭. 소모품 사용 또는 소환 확인창이 떠야 한다. E로 소모품이 사용되면 결함이다. 제작 화면의 E 제작·제련, 장비 화면의 E 장착·해제는 유지된다.
5. **설치 확정:** 흙·차열벽·벽지·단열 문·화로 등에서 초록 미리보기 → 우클릭을 각각 확인한다. 좌클릭으로 설치되면 결함이다. 붉은 미리보기에서 우클릭해도 재료가 줄어들면 안 된다.
6. **마지막 한 개:** 설치 아이템이 한 개 남았을 때 설치한다. 설치 확정 클릭이 다른 아이템 사용·시설 열기·부채 공격까지 동시에 발생시키면 결함이다.
7. **취소:** 미리보기에서 Esc를 한 번 누른다. 미리보기만 없어지고 재료가 유지되어야 한다. 같은 입력에 일시정지 메뉴까지 열리면 결함이다. 그 다음 Esc는 정상적으로 일시정지를 연다.
8. **기존 입력:** 미리보기를 취소한 뒤 좌클릭 공격·채굴·설치물 회수, F 부채 능력, Shift+우클릭 벽지 제거를 확인한다.
9. **소환 확인:** 인벤에서 소환품 우클릭 → 확인창. Esc 취소 시 소환품이 남고 보스가 나오지 않아야 한다. 다시 우클릭으로 열고 우클릭으로 확정하면 정상적으로 소환·소모되어야 한다.
10. **안내 문구:** 설치 확정은 우클릭, 시설 사용은 E, 소모품 사용은 우클릭으로 표시되어야 한다. 인벤토리 도움말·제작 후 설치 안내·소환 확인창도 확인한다.

## 5. 오프닝 — 현재와 아트 도착 후를 구분

현재 확인할 것:
- 새 게임이 빈 오프닝 화면에 멈추지 않고 시작 특성 선택으로 넘어가는지.
- 특성 선택 후 플레이와 저장이 되는지.
- 이어하기에서 오프닝이나 이미 선택한 특성 화면이 다시 나타나지 않는지.

아트 도착 후 연결 위치:
- `Assets/Art/Gameplay/GameplayArtCatalog.asset`의 Opening Illustrations에 순서대로 3장을 등록한다.
- 전역값 `opening_illust_pages=3`을 사용한다. 세 장 중 한 장이라도 없으면 오프닝 전체를 건너뛴다.
- 새 게임에서 1/3 → 2/3 → 3/3 → 특성 선택을 확인한다.
- 다음 버튼 또는 E/Space는 다음 장, Esc는 특성 선택으로 건너뛰기다. 화면 비율을 유지한다.
- 오프닝 중 세계 시간·플레이어 입력이 멈추고 특성 선택 완료 후 정상 재개되어야 한다.
- 이어하기에서는 오프닝을 재생하지 않는다.

## 검증 범위

- 정적 코드 흐름 검토와 CPU 기반 런타임/에디터 C# 프로젝트 컴파일만 수행한다.
- Unity MCP로 연결된 에디터의 비실행 상태, 실제 전역 데이터, 아트 카탈로그 오프닝 수, 얼음 호수 타일의 스프라이트·Grid 충돌 설정을 읽어 확인했다.
