# 무기 공격 모션 위치 전수조사

## 확인 범위
- player-combat.csv와 실제 GameDataCatalog의 전투 프로필 19종 전부.
- GameplayArtCatalog의 전용 공격 모션 13종, 83프레임 전부의 rect/pivot/PPU를 Unity MCP로 읽기 전용 조사.
- 나머지 발톱 6종은 기본 공격 5프레임을 공유한다. 기본 캐릭터 idle/walk/jump/attack 연결 및 프레임 교체 코드 확인.
- PNG 원본 24프레임의 투명 여백을 CPU로 확인.
- 게임 실행, GPU 검증, 리소스 수정은 하지 않았다.

## 원인
- 기본 캐릭터 idle는 발바닥 피벗: rect 17×30, pivot (8,0), PPU16.
- 기존 전용 공격 10종의 59프레임은 모두 pivot.y=0.
- 새 PNG 공격 3종의 24프레임은 32×32, pivot (16,16), PPU16으로 이미지 중앙이 기준이다. 모든 PNG의 불투명 영역은 이미지 아래 끝까지 존재한다.
- MainGamePlayerController는 idle 기준으로 Visual의 크기와 발 위치를 한 번 정한다. RuntimeCharacterSpriteAnimator.ApplyFrame은 sprite만 교체한다.
- 따라서 새 공격은 발바닥이 기본 기준점보다 16소스픽셀 아래로 내려간다. 기본 높이 30픽셀을 2타일로 정규화하므로 약 1.067타일 차이다.
- PlayWeaponAttack 호출 흐름은 본체 위치/콜라이더를 재배치하지 않는다. 확인된 원인은 렌더링 기준점 불일치다.
- LoadDeliveredMiscFrames는 PNG를 Sprite Single, PPU16으로 설정하지만 발 기준 피벗은 설정하지 않아서 기본 중앙 피벗이 남았다. Aseprite 원본이 연결된 기존 모션과 가져오기 경로가 다르다.

## 수정 방향
- 3종의 공격 PNG 24프레임을 기존 캐릭터와 같은 발 기준 피벗으로 맞춘다. 원본 캔버스가 32×32이고 발이 아래 끝에 있으므로 (0.5,0) 정규화 피벗이 기준이다.
- 재연결 시 재발하지 않도록 공격 PNG 가져오기 코드에도 동일한 규칙을 명시한다.
- LoadDeliveredMiscFrames는 밀폐 서리 파동과도 공유하므로 모든 PNG에 일괄 적용하지 말고 무기 공격에만 적용해야 한다.
- 본체 이동이나 물리 위치 보정으로 해결하지 않는다.

## 수정 완료
- 신기전 손대 8, 한파 신기전 9, 얼음뿌리 채찍선 7프레임 모두 Sprite Editor data provider의 EditPivot 지원 확인 후 피벗을 수정했다.
- 실제 카탈로그 참조 24개가 32×32, PPU16, 픽셀 피벗 (16,0)임을 Unity MCP로 확인했다.
- LoadDeliveredMiscFrames의 무기 공격 3종에만 동일한 발 기준 정렬을 적용해 재연결 시에도 유지한다. 공용 로더의 파동·버튼·보스바에는 적용하지 않는다.
- 본체/콜라이더 위치, 원본 픽셀, 공격 판정과 타이밍은 변경하지 않았다.
- CPU 기반 런타임/에디터 C# 컴파일 오류 0개. 게임 실행 및 GPU 검증은 하지 않았다.
