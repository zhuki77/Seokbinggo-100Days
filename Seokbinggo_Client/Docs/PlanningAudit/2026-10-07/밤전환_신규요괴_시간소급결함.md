# 밤 전환 신규 요괴의 시간 소급 결함

## 관찰과 증거의 범위

사용자는 밤 시작 직후에도 요괴가 근처에 없었으며 이후 플레이어/코어 방향으로 접근했다고 보고했다. 앞서 확인한 6일차 밤 +35.9초 저장에서 플레이어 x=300.71, 도깨비 x=379.38, 불가사리 x=414.65였다. 저장 위치를 최초 소환 위치로 간주하거나 이후에 멀어졌다고 추정해서는 안 된다. 해당 저장에는 생성 좌표와 첫 Tick 시간이 기록되지 않아 당시의 정확한 이동 경로는 확정할 수 없다.

## 확인한 코드 결함

1. BedService의 낮 휴식은 DayNightService.AdvanceToNextPhase를 통해 남은 낮 시간을 한 번의 Tick으로 넘긴다. TimeScale 배속으로 경계를 넘는 경우에도 동일한 이벤트 흐름을 사용한다.
2. DayNightService.Tick 안에서 NightStart가 발행되고 MainGameEncounterCoordinator가 요괴를 생성한다. MainGameRuntimeServices.Register가 새 YokaiBrain을 CentralTickDriver에 등록한다. 제품 소환 경로는 별도의 SetGameSecondsSource를 연결하지 않아 중앙 공급을 받는다.
3. 기존 CentralTickDriver는 등록 시각을 보관하지 않고 직전 LateUpdate 이후의 전체 시간을 모든 소비자에게 전달했다. 예를 들어 낮 450초에서 휴식하여 밤 900초가 되면 방금 생긴 요괴도 450초를 첫 Tick으로 받는다.
4. YokaiBrain.MoveTowardAttackRange는 이동 속도 × 전달 시간으로 이동량을 계산한다. 공격 직선이 막히면 목표까지의 거리로 이동량을 제한하지 않는다. 우회 방향을 한 번 결정하고 WorldMobPhysicsBody.Move에 큰 이동량을 전달하므로 첫 렌더링 전에 소환 지점에서 크게 벗어날 수 있는 경로가 있다. 실제 이동량은 충돌 지형에 따라 달라진다. 생성 후보 반경 12~24를 늘리는 기획과는 별개인 결함이다.
5. 기존 DayNightService는 Tick 전체 시간을 경계 이벤트 전에 GameSeconds에 미리 더했다. 등록 시각만 고치면 경계를 지난 뒤 같은 Tick에서 흐른 밤 시간까지 누락되므로 이 부분도 함께 수정했다.

## 변경

- CentralTickDriver는 소비자마다 등록/마지막 전달 시각을 보관한다. 중복 등록은 시각을 초기화하지 않는다. 해제된 소비자는 스냅샷에 남아도 Tick하지 않는다. Configure 또는 유효한 시계 역행 시 기준 시각을 맞춘다.
- DayNightService는 낮/밤/경고/새벽 구간을 실제로 진행한 만큼 GameSeconds를 누적하고 나서 경계 이벤트를 발행한다. 이벤트의 순서는 유지하며 총 전달 시간은 각 구간의 합이다.
- 일반/침공 요괴와 객귀의 소환 로그에 인스턴스 ID, 종류, 날짜, 실제 생성 좌표, 플레이어 좌표와 생성 시각을 남긴다. 기존 객귀 전용 로그 제목은 `Yokai spawned`로 변경했다.
- 기존 저장의 멀어진 요괴 위치를 임의로 되돌리지 않는다. 최초 좌표를 복구할 근거가 없기 때문이다.

## 코드 흐름 검토

다음은 실행한 테스트 결과가 아니라 수정된 코드의 시간 계산 검토다.

| 경로 | 기존 소비자 | 밤 경계에서 생성한 소비자 |
|---|---|---|
| 낮 450 → 휴식 → 밤 900 | 450초 | 0초, 다음 프레임부터 실제 진행 시간 |
| 낮 899 → 2초 Tick → 밤 901 | 2초 | 생성 시각 900부터 1초 |
| 중앙 Tick 콜백 안에서 생성 | 해당 소비자의 실제 누적 시간 | 이번 스냅샷에 없으며 다음 프레임의 실제 시간부터 |
| 중복 Register | 등록 시각 유지 | 누락/이중 전달 없음 |
| Unregister | 이후 Tick 없음 | 같은 프레임 스냅샷에 있어도 해제 확인 후 제외 |

## 검증 수준

CPU 기반 런타임/에디터 C# 컴파일로 문법과 참조만 확인했다. 최종 빌드는 런타임 오류 0/경고 3, 에디터 오류 0/경고 38이다. 게임, Play Mode, CPU 시뮬레이션 테스트 및 GPU 검증은 실행하지 않았다. Unity MCP로 에디터 상태와 콘솔만 읽었다. 기존 guideDay 0→1 저장 왕복 오류가 콘솔에 남아 있어 콘솔 전체가 정상이라고 주장하지 않는다.

실제 플레이에서 다시 낮 휴식으로 밤에 진입한 뒤 소환 로그의 position과 곧바로 저장한 요괴 위치를 비교하면 이번 수정의 동작을 확인할 수 있다. 이전 저장을 단순 이어하기하는 것은 새 소환 시점 검증이 아니다.
