# 드랍템 매몰 탈출 재설계

2026-10-07 사용자 요청: 타일 설치로 막힌 드랍템은 최단 경로로 열린 공간에 나오게 한다.

후속 수정: 배경처럼 실제 충돌이 없는 곳에서 탈출하면 안 된다는 사용자 지시를 반영했다. 탈출 시작/탐색/종료의 장애물 판정을 타일 데이터의 BlocksMovement 및 칸 사각형에서 Physics2D.OverlapCircle의 실제 Collider2D 겹침으로 교체했다. 레이어 충돌 마스크와 개별 IgnoreCollision을 적용하며 트리거, 플레이어, 요괴, 다른 드랍템은 기존 충돌 제외 계약에 따라 제외한다. 지도 경계는 출구 후보 제한에만 쓰며 매몰 판정으로 삼지 않는다. 저장의 escapingTiles가 true여도 복원 위치에 실제 겹침이 없으면 탈출을 시작하지 않는다. Unity MCP reflection으로 사용 API 시그니처를 확인했다.

이전 구현은 일부 방향의 도착 좌표만 검사하고 Rigidbody 위치를 바로 변경했다. 8타일 탐색을 제거한 뒤에도 경로 이동은 없었고, 못 빠져나온 물체에는 일반 물리 밀어내기와 자석 흡입이 계속 적용됐다. 이번에는 그 위치 보정 코드를 교체했다.

- 실제 위치를 출발점으로 하는 0.25타일 격자, 상하좌우 동일 비용 BFS를 사용한다. 첫 번째 열린 지점까지 역추적한 경로가 해당 격자에서 최단 경로다. 열린 지점은 반지름 0.22인 드랍 충돌체 전체와 추가 여유 0.02가 전경 타일에 겹치지 않는 위치다.
- 이미 매몰된 상태에서 빠져나오는 처리이므로 막힌 격자도 탐색한다. 일반 이동 AI의 통행 규칙과 목적이 다르다. 지도 밖은 출구로 사용하지 않는다.
- 도착점으로 순간 이동하지 않는다. 초당 4타일, 프레임당 최대 0.2월드 단위로 경로를 따라 움직인다. 게임의 1타일=1월드 단위 계약을 사용한다.
- 탈출 중 Rigidbody.simulated를 끄고 속도를 0으로 한다. 자석/일반 줍기/까치 회수/절도는 탈출이 끝난 후 다시 허용한다. 드랍 아이템과 수량은 유지한다.
- 설치/철거/밀폐 상태 변경 시 현재 위치에서 경로를 다시 구한다. 저장은 현재 위치와 탈출 상태를 보관하며 이어하기에서 경로를 재계산한다. 기존 저장의 매몰 드랍도 겹침 검출로 탈출 상태에 진입한다. 정상 바닥 접촉의 작은 오차는 매몰로 취급하지 않는다.
- 단일 탐색은 8192노드로 제한한다. 그 안에서 출구가 확인되지 않으면 현재 위치에서 아이템을 보존하고 지형 변경 때 다시 탐색한다. 임의의 먼 위치로 보내거나 물리 밀어내기를 재개하지 않는다.

검증은 코드 흐름 검토와 CPU C# 컴파일만 진행했다. 런타임 오류 0/경고 3, 에디터 오류 0/경고 38. Unity/게임/Play Mode 및 시뮬레이션 테스트는 실행하지 않았다.

플레이 확인: 드랍 위에 한 칸 설치 → 인접 출구까지 부드럽게 이동. 천장을 막고 옆을 열어 설치 → 가까운 옆 출구 선택. 이동 중 추가 설치/철거 → 현재 위치에서 재탐색. 탈출 중 저장·이어하기 → 수량 유지 및 탈출 재개. 빠져나온 뒤 자석 회수·절도·까치 회수 재개.
