# 객귀 및 백중날 소환 결함

후속 조사: [밤 전환 신규 요괴의 시간 소급 결함](밤전환_신규요괴_시간소급결함.md)에서 첫 Tick에 생성 전 시간이 전달되는 별도 결함을 확인하고 수정했다. 현재 소환 로그 이름은 `Yokai spawned`이며 객귀 외 일반/침공 요괴의 생성 좌표와 시각도 기록한다. 아래 검증 기록은 앞선 작업 당시의 기록이다.

## 실제 저장에서 확인한 상태

2026-10-07 19:04:43 저장은 15일차 밤 +20.43초, 백중날 nextWaveIndex=1이다. 객귀 yokai_36은 raid=false, HP 3240/3240, 위치 (584.29,145.07)이고 플레이어는 (296.79,139.40)이다. 불가사리도 (579.01,143.86)에 있었다. UI는 살아 있는 객귀를 거리와 무관하게 찾으므로 화면 밖 개체도 체력이 표시된다. 객귀 아트 연결은 존재한다. 정본은 day-events.csv의 2파 +150초 등장이다.

## 원인과 수정

1. 이어하기의 RebuildBaekjungBindings가 백중날 OnNightStart 구독을 다시 등록하면서 일반 소환 핸들러보다 뒤로 간다. 기존 일반 소환은 scheduler.IsActive에 의존하므로 이 순서에서는 15일차 day-curve 전체 12마리를 일반 소환한다. 정상 구독 순서라도 일반 대기열을 생성해 두어 새벽에 재개될 여지가 있었다. 이제 실제 달력의 DayEvents 날짜로 일반 소환과 대기열 작성을 차단한다. 스케줄러 콜백 순서에 의존하지 않는다.
2. 기존 요괴 소환은 발 칸 중심(y+0.5)에 충돌체 중심을 놓았다. 반지름 .84인 불가사리와 1.26인 객귀가 바닥과 겹친다. 이제 바닥 윗면+충돌 반지름+0.02에 중심을 놓으며, 원형 충돌체 전체에 대해 맵 경계·천장·옆벽 겹침을 검사한 후보만 지형 가중치 선택에 전달한다. 열린 문은 통과 공간으로 처리한다. 몸집·공격 범위·이동 속도는 바꾸지 않는다.
3. 지상 본체의 발 정렬이 스프라이트 연결 전에 실행되어 이미지 바닥 높이를 사용하지 못했다. 아트/애니메이터 Configure 이후 계산하도록 옮겼다.
4. 알려진 이전 저장의 잘못된 일반 객귀(이벤트 밤, raid=false, 2파 이전)만 복원에서 제외한다. 저장된 백중날 시계/파동 인덱스는 그대로 두므로 +150초에 정상 객귀가 소환된다. 실제 raid 객귀, 2파 이후 저장, 다른 요괴와 절도품은 보존한다. 저장 파일을 직접 수정하지 않는다.
5. 객귀 소환 시 raid 여부, 날짜, 파동 수, 실제 생성 위치와 플레이어 위치를 로그에 남겨 후속 위치 문제를 구분할 수 있게 했다. 화면 밖 체력 UI를 감추어 증상을 숨기지는 않는다.

## 검증

- 실제 BaekjungScheduler/BaekjungWaveSpawner와 현재 소스에서 추출한 일반 밤 핸들러/소환 위치 함수를 CPU 검사했다. 구독 순서 두 가지, +149초 없음/+150초 1마리, 총 12마리 및 새벽 일반 대기열 없음, 몸집 3종의 발 높이, 낮은 천장/옆벽/경계 배제, 이전 잘못된 객귀 복원 조건 등 28/28 통과.
- 기존 달력 가드를 제거한 음성 대조군은 이어하기 구독 순서에서 일반 소환 없음 검사에 실패하여 중복 소환 경로를 재현했다. 정상 순서에서도 새벽 대기열 검사가 실패했다. 최종 추출본은 수정된 현재 소스로 다시 생성했다.
- CPU C# 컴파일: 런타임 오류 0/경고 3, 에디터 오류 0/경고 38. Unity MCP 콘솔에는 기존 guideDay 0→1 저장 왕복 검증 오류 두 건이 남아 있으며 이번 변경의 컴파일 오류는 확인되지 않았다.
- 재실행: `python -X utf8 Docs/PlanningAudit/2026-10-07/Day15CpuChecks/prepare.py` 이후 `dotnet run --project Docs/PlanningAudit/2026-10-07/Day15CpuChecks/Day15CpuChecks.csproj --no-restore`. 스텁은 Unity 물리 실행을 대신하지 않는다.
- Unity/게임/Play Mode를 시작하거나 GPU 검증을 하지 않았다. 저장의 288타일 이동을 물리 시뮬레이션으로 재현한 것은 아니므로 그것이 바닥 겹침만의 결과라고 단정하지 않는다. 확인된 생성 겹침과 발 정렬 결함을 제거한 상태다.

## 사용자 플레이 확인

15일차 밤 +20초의 기존 저장을 이어한다. 2파 이전에 잘못 소환된 일반 객귀 체력 표시가 없어야 한다. 배속을 1로 두고 +150초까지 진행하면 객귀 한 마리가 정상 높이로 등장해야 한다. +300초까지 총 편성은 12마리이며 일반 편성이 추가로 12마리 겹치면 안 된다. 객귀가 나타난 이후 다시 저장·이어하기하면 위치/체력/패턴이 유지되어야 한다. 객귀 본체와 불가사리는 지면에 파묻혀 생성되지 않아야 한다. 계속 화면 밖에만 남으면 Gaekgwi spawned 로그의 생성 위치와 이후 저장 위치를 비교한다.
