# 상단 안내 아이템 이름 전수조사 및 수정

## 조사 범위
- 상단 현재 목표 패널: 목표 제목, GuideQueue 문구, 보상 제작 연결, 보관/밀폐/침공/보스 안내, 새벽 결과.
- 상단 외부 상호작용 메시지: ShowExternalMessage의 호출처와 메시지를 생성하는 승급·재냉각·부적·보금자리·시설 런타임.
- 기존 HUD의 보금자리/시설 제작 가이드와 장비 관련 제목/테스트 지급 문구, 보스 선택 화면.
- CSV 안내 문구 38개 및 Unity MCP 실제 GameDataCatalog 아이템 171개와 제작 결과 이름.

## 발견과 변경
| 경로 | 발견 | 수정 |
|---|---|---|
| 석빙고 승급 | 재료 부족/소모 실패에서 itemId 직접 출력 | 인게임 재료 이름 출력 |
| 보상 제작 연결 | 재료 이름 조회 실패 시 ID 출력 | 공통 이름 조회, 결과 아이템도 동일 조회 |
| 밀폐 경고 2곳 | 블록 이름 조회 실패 시 ID 출력 | 공통 이름 조회 |
| 시설 설치 상한/회수/연료 | 공용 ItemName이 실패 시 ID 출력 | 공통 이름 조회 |
| 회복 아이템 사용 | 조회 실패 시 ID 출력 | 공통 이름 조회 |
| 활성 장비 전환 | 이름 조회 실패 시 빈 이름 | 공통 이름 조회 |
| HUD 시설 추천 | 제작식 조회 실패 시 recipeId 출력 | 출력 아이템/시설 이름 조회 |
| 장비 제목/테스트 지급 | 장비 ID 대체/직접 출력 | 공통 이름 조회 |
| 보스 선택 상세 | 이름 옆 내부 보스 ID 병기 | 인게임 이름만 표시 |

- GameDataCatalog.ItemDisplayName은 아이템 → 모듈 → 광물의 DisplayName을 조회한다. 빈 이름/ID와 같은 이름은 인게임 명칭으로 인정하지 않는다.
- 데이터가 없는 예외 상황에서도 ID 대신 문맥에 맞는 '재료', '설치물', '블록', '장비' 등을 표시한다.
- 현재 적재된 171개 아이템 및 제작 결과에서 빈 이름/ID와 같은 이름은 0건이었다. 데이터 이름 자체가 아닌 메시지 조립 경로의 결함이었다.
- CSV의 표시 문구 38개에는 내부 ID 형식의 리터럴이 없었다. 트리거·컨텍스트·저장 ID는 내부 식별자로 유지한다.
- 재냉각/부적/휴식/보관/보스 이벤트의 기존 한국어 문구는 확인 후 유지했다. 콘솔 진단 로그의 ID는 유지한다.

## 검증
- CPU C# 런타임 및 에디터 컴파일 오류 0개. 최종 에디터 빌드에서는 런타임 의존 프로젝트도 함께 재컴파일되었다.
- Unity MCP 콘솔 오류 0개.
- 정지 상태 Editor에서 실제 카탈로그 이름 연결 확인: club_shard→도깨비 방망이 조각, ice_shard→얼음 조각, icesteel_ingot→얼음강철 주괴, ice_crystal_cooler→빙정 냉각로.
- 게임 실행/Play Mode/GPU 검증은 하지 않았다. 실제 메시지 노출 동작은 코드 흐름으로 검토했다.
- 플레이 확인: 석빙고 승급 재료 부족, 새 보상 줍기, 비밀폐 블록 설치, 시설 연료 부족, Q 장비 전환, 회복 아이템 사용 시 이름 표시 확인.
