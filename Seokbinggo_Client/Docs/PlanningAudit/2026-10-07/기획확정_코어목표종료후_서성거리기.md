# 코어 목표 종료 후 대기 및 플레이어 인식

2026-10-07 사용자 확정. 이전의 코어 침투 성공 즉시 Retreat 및 일반 요괴의 즉시 플레이어 교전 제안보다 이 지시가 우선한다.

추가 확정: 코어가 여러 개이면 현재 코어 행동 완료 직후 다른 미완료 코어를 목표로 접근한다. 현재 위치에서 가까운 순서로 선택하고, 같은 거리에서는 셀 x/y 순서로 결정한다. 모든 현재 코어의 행동이 완료되어야 아래의 대기/서성거리기 및 플레이어 인식으로 전환한다. 최초 목표 선택의 기존 거점 반경 28타일은 유지하고, 이후 코어 순회에는 그 반경을 적용하지 않는다.

코어별 목표 앵커를 분리하여 한 요괴의 다음 코어 선택이 다른 요괴의 목표 위치를 바꾸지 않도록 했다. 실제 설치 목록(MainGameEnvironmentState.CopyIceCoreCells)이 현재 코어의 출처다. 철거된 현재 코어는 건너뛰고 다음 미완료 코어로 전환한다. 요괴별 완료 코어 셀 목록과 현재 목표 코어 셀을 저장하여 이어하기에서 완료한 코어를 다시 선택하지 않는다. 침투 열 누적은 기존 개체당 한 번 기준을 유지하며 코어 수로 배증시키지 않는다.

단일 코어 대기 상태의 이전 저장에는 코어 목록이 없다. 복원 시 기존 기준 코어를 완료한 것으로 간주하고 나머지 코어를 선택한다. 이미 플레이어와 교전/절도/새벽 도주 중인 이전 상태는 강제로 코어 순회로 바꾸지 않는다.

## 확정 동작

- 최신 사용자 확정: 진입로가 열리면 추가 벽 파괴만 멈추고, 해당 코어까지 접근을 계속한다. 실제 코어 도달 시 정규 침공 열기를 기록한 다음 해당 코어 목표를 완료한다. 남은 코어가 있으면 다음 코어로, 없으면 코어 도달 위치에서 대기로 전환한다. 일반 밤에는 기존처럼 침공 열기가 누적되지 않는다.
- 후속 사용자 확정: 여러 요괴가 같은 방향·시간으로 서성거리는 현상을 없앤다. 대기 시작 위치에서 좌우 중 무작위 방향으로 1타일 이동하고 원점으로 돌아온 뒤 다시 방향을 선택한다. 초기 대기 및 각 이동 사이 멈춤은 개체별 독립 난수로 0.4~1.3 게임초를 선택한다. 이동 속도는 기존 속도와 1타일/게임초 중 작은 값이며 한 Tick에서 목표점을 지나치지 않는다. 저장 당시 이동 단계와 남은 대기 시간은 기존 필드로 유지한다.
- 실제 벽/닫힌 문이 막거나 지상형의 발밑 지지대가 끊기는 방향은 건너뛴다. 서성거리기 때문에 벽을 파괴하거나 낭떠러지로 향하지 않는다.
- 플레이어가 기존 종별 AggroRadius 안에 들어오면 기존 추적/접촉 공격으로 연결한다. 은신 판정은 유지한다. 야광귀도 먼저 대기한 뒤 플레이어를 인식하면 기존 절도 → 성공 시 도주 행동으로 연결한다.
- 새벽 도주, 종별 체/등불 카운터, 감속, 강제 어그로, 보스전 일시정지는 기존 처리에 연결한다.

## 구현 및 저장

YokaiBrain의 기존 행동 번호 0~4는 유지하고 CoreIdle=5를 추가했다. 코어 목표 완료 여부, 파괴 접근 여부, 대기 기준 위치/왕복 단계/남은 정지 시간을 저장한다. 플레이어 추적에 들어간 뒤에도 완료 여부가 유지되므로 이어하기에서 코어를 다시 목표로 삼지 않는다. 제품 생성 경로가 플레이어 대상을 명시적으로 전달하여 현재 위치가 거점 범위를 벗어난 저장도 목표를 복원할 수 있다.

MainGameEncounterCoordinator의 사전 저장 검증과 YokaiBrain 복원 모두 같은 새 상태 검증을 사용한다. 기존 필드 누락은 기본값으로 읽는다. 이전 저장에서 침투 기록 직후 Retreat 상태인 일반 요괴는 현재 자리의 대기로 전환한다. 야광귀의 이미 진행된 절도 도주와 모든 새벽 도주는 보존한다.

처음 목표를 선택할 때와 벽 타격·파괴/철거·밀폐 변경 후 실제 통과 가능한 전체 경로를 확인한다. 열린 경로가 있으면 벽 파괴를 가정하는 이동 경로를 사용하지 않고 실제 전체 몸집이 통과 가능한 길을 따라 코어로 이동한다. 지상형은 코어와 높이가 비슷해도 열린 길을 따르도록 경로 탐색을 사용한다. 경로가 다시 막히면 벽 파괴를 포함한 접근으로 돌아간다. 매 프레임 전체 경로 탐색을 하지 않는다.

추가 사용자 확인 반영: 경로 개통 검사는 실제 콜라이더 전체 폭/높이를 사용한다. 벽 공격 대상도 중심점 반경 대신 전체 콜라이더의 진행 방향 이동 영역과 겹치는 설치 벽 중 가장 먼저 막는 칸을 선택한다. 바닥 접촉은 CollisionSkin 여유를 제외하여 진행 방향의 벽으로 오인하지 않는다. 2~3칸 몸집의 위쪽 잔여 벽도 공격 대상에 포함되며 전체 몸집이 통과하는 경로가 열릴 때까지 공격을 계속한다. OnTilePlaced를 직접 구독해 전체 밀폐 여부 변화가 없는 재설치도 경로 재검사를 요청한다. 열린 경로가 사라지면 파괴 가능한 벽을 고려하는 탐색과 벽 공격을 다시 허용한다. 다른 열린 길이 남아 있으면 그 길을 따라 이동한다.

침공 온도 기록은 실제 코어 도달 기준 및 개체당 한 번 기준을 유지한다. 코어 목표는 경로 개통만으로 종료하지 않는다. 대기 후 플레이어를 목표로 이동할 때에는 플레이어까지 막는 구조물에 대한 기존 전투 처리가 적용된다. hasCoreArrivalGoalState로 새 저장을 구분한다. 이전 저장에서 코어 도달 없이 대기 중이고 침투 기록이 없는 개체는 완료 코어 목록을 비우고 현재 남아 있는 코어로 다시 접근한다. 기존 플레이어 교전·절도·새벽 도주 상태는 보존한다.

## 검토 및 플레이 확인

게임/Play Mode/CPU 시뮬레이션 테스트/GPU 검증은 실행하지 않았다. 상태 전환과 저장 복원은 코드 흐름으로 검토했고 CPU C# 컴파일로 문법·참조만 확인했다. 최종 빌드는 런타임 오류 0/경고 3, 에디터 오류 0/경고 38이다.

사용자 확인 순서:

1. 새벽 경고 전 침공 밤에 플레이어를 해당 요괴의 인식 범위 밖에 둔다. 요괴가 진입로를 열면 추가 벽 파괴를 멈추고 코어까지 이동해야 한다. 도달 시 열기가 개체당 한 번 증가하고, 남은 코어가 없으면 그 부근에서 짧게 왕복해야 한다.
2. 몸집 2~3칸 요괴는 일부만 열린 구멍을 통과 가능한 경로로 판단하지 않아야 한다.
3. 인식 범위 밖에서는 서성거리다가 플레이어가 범위에 들어오면 기존 추적·공격을 시작해야 한다. 야광귀는 플레이어 인식 후 절도하며 실제 절도 성공 전에는 도주하면 안 된다.
4. 벽/낭떠러지 옆에서는 안전한 쪽만 왕복해야 한다. 대기 중 공격 애니메이션이나 추가 벽 피해가 발생하면 안 된다.
5. 대기 중 저장·이어하기하면 같은 기준점에서 대기를 이어가고, 플레이어 추적 중 저장·이어하기하면 코어 접근으로 되돌아가지 않아야 한다.
6. 새벽 경고에서는 기존 raid 도주가 적용되어야 한다. 심층 resident 규칙은 변경하지 않았다.
7. 코어 두 개를 서로 다른 방에 설치한다. 첫 코어의 진입로를 열고 실제 첫 코어까지 도달한 다음 두 번째 코어로 접근한다. 두 번째 코어까지 도달해야 서성거리기를 시작하며 동일 개체의 열기는 중복 누적하지 않는다.
8. 두 번째 코어로 이동 중 저장·이어하기한다. 첫 코어로 되돌아가지 않고 저장된 두 번째 코어를 목표로 유지해야 한다. 두 요괴가 서로 다른 코어를 목표로 할 때 한 개체의 목표 전환이 다른 개체의 목표 좌표를 움직이면 안 된다.
9. 현재 목표 코어를 철거하면 남은 미완료 코어를 선택해야 한다. 남은 코어가 없으면 대기로 전환해야 한다.
