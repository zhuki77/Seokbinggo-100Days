## 구현

1. 밀폐 경계 채굴 경고

- 기존 플레이어의 실제 채굴 조준 셀 이벤트를 사용한다. 채굴 가능한 조준 칸을 제거하면 현재 코어 밀폐가 깨지는 경우에만 주황색 테두리와 seal_boundary_dig 문구를 표시한다.
- SealSystem.WouldBreakCoreSeal은 기존 코어 창 Flood Fill을 재사용하며 제거한 셀을 가상의 공기로 취급한다. 단열문은 위아래 2칸을 함께 제거한다. 실제 타일·문 상태·변경 이력·Revision을 바꾸지 않는다.
- 내부 기둥, 뒤에 다른 인정된 벽이 있는 이중벽, 이미 밀폐가 깨진 방은 밀폐 파괴 경고 대상이 아니다. 조준/밀폐 Revision/코어가 바뀔 때 다시 계산한다. 채굴을 막는 기능은 아니다.

2. 화면 밖 거점 방향

- 가장 가까운 설치 코어가 화면 밖이면 기존 GoalDirectionArrow 아트로 원본 색상의 화살표와 거점 이름을 화면 가장자리에 표시한다. 코어가 보이거나 없으면 숨긴다.
- 화면 좌표를 Canvas 로컬 좌표로 변환해 가로세로 비율을 반영하고, 가장자리 여백 안으로 제한한다. 거점 이름은 화살표 각도와 반대로 회전시켜 읽을 수 있게 유지한다.
- 기존 목표 화살표의 목표가 같은 코어이면 중복 화살표를 숨긴다. 서로 다른 목표를 가리킬 때는 두 표시가 존재할 수 있다. 메뉴·일시정지·사망·전환 중에는 숨긴다.

3. 침공 후 복구 체크

- 실제 TileService.TryDamageWall 성공 파괴에서만 WallDestroyedByDamage(문 아래칸/발자국 높이)를 발행한다. 부분 피격·플레이어 채굴은 파괴 칸 기록이 아니다.
- 침공 밤에 현재 거점의 코어 창 안에서 파괴된 셀만 별도 목록에 기록한다. 1×2 문은 2칸이며 중복 제거한다. 일반 설계 구멍/누출 후보와 합치지 않는다.
- 후속 사용자 확정: 정규 침공 다음 날 낮부터 우측 상단에 ① 열기 제거(잔량 ℃) ② 문·벽 파괴 칸 수리(남은 칸) ③ 보관 조건(충족 장독/판정 장독)을 각각 표시한다. 완료 전에는 이후 낮에도 유지하고, 세 조건을 모두 충족하면 해당 침공 회차의 완료를 기록하여 숨긴다. 같은 회차에서 상태가 다시 나빠져도 재표시하지 않으며 다음 침공 다음 날 낮에 새 회차를 시작한다. 밤에는 숨긴다. 파괴·침투 기록이 없는 침공도 일정 기준으로 회차를 시작한다.
- 열기 >0에서 0으로 바뀔 때 heat_cleared CSV 안내를 한 번 발행한다. 손상 칸이 남으면 base_damaged의 n칸 안내는 별도로 유지한다.
- 파괴 칸에 현재 인정되는 밀폐 구조물이 복구됐을 때만 기록에서 제거한다. 밀폐가 되지 않는 직접 놓은 흙·돌은 수리로 처리하지 않는다.
- 보관 조건은 실제 StorageTemperatureService의 현재 판정을 사용한다. 해당 코어 창 안에서 보관 요구가 있는 장독들을 확인하며, 대상이 없으면 보관할 물품을 넣도록 표시한다. 열기 0 또는 구조 수리 0만으로 보관 성공을 만들지 않는다.

## 저장과 영역

SaveGame의 선택 필드 invasionBrokenCells/invasionLastBaseAttackDay/invasionLastCompletedRecoveryDay를 캡처·복원에 연결했다. 기존 schema 31을 유지한다. 완료된 침공 회차는 이어하기 후에도 재표시하지 않는다. 구 저장의 완료 일자 누락은 0으로 읽어 현재 조건으로 평가한다. 유효하지 않은 복원 좌표/음수 일자는 거부하고 기존 목록을 변경하지 않는다. 월드 교체 시 타일 파괴 구독을 교체하며 런타임 종료 시 이벤트를 해제한다.

S7 도입 전 저장에는 침공 파괴 목록이 없으므로 과거 타일 제거를 침공 손상으로 추측하지 않는다. 새로운 침공에서 파괴된 칸부터 기록한다. 기존 침공 열기 기록은 그대로 사용한다.

A: SealSystem 제거 시뮬레이션, TileService 파괴 원인 이벤트, MainGameBuildingGuide 유지 상태. B: 목표/건축 HUD 및 유지 목록 저장 연결. 사용자 S7 전체 진행 요청에 따라 함께 연결했다. 기존 타일 판정·채굴·전투·재냉각 비용·드롭·기획 확정 변경은 유지한다.

## 실제 플레이 확인

1. 코어가 있는 밀폐된 방에서 가까운 경계벽·바닥·지붕을 채굴 조준한다. 이 칸 제거가 밀폐를 깨뜨리는 경우 주황 테두리와 이 칸을 캐면 밀폐가 깨져요 문구가 나와야 한다. 내부 기둥/공기/안전한 이중벽을 조준하면 경고가 없어야 한다. 경고 확인만으로 블록이 없어지거나 문이 열리면 결함이다.
2. 닫힌 문 위칸/아래칸 채굴을 조준한다. 실제 한 문 제거가 밀폐를 깨면 경고해야 한다. 문을 이미 열어 밀폐가 깨진 경우에는 현재 밀폐를 깨뜨린다는 경고가 없어야 한다.
3. 거점 코어가 화면 밖이 되도록 좌우·상하로 이동한다. 원본 색상의 거점 화살표가 적절한 가장자리를 가리키고 이름은 읽을 수 있어야 한다. 코어가 화면 안에 들어오면 숨겨야 한다. 가방/제작/일시정지에서는 숨겨야 한다.
4. S7 적용 후 실제 침공 밤에 문·벽을 파괴당한다. 부분 피격과 완전 파괴를 구분해 완전 파괴만 기록한다. 문 하나가 파괴되면 2칸이다. 기존 누출/설계 구멍을 침공 파괴 수에 더하지 않아야 한다.
5. 다음 낮에 복구 세 줄을 확인한다. 재냉각만 먼저 하면 열기만 완료되어야 한다. 파괴 칸과 보관 조건은 각각 미충족 상태를 유지해야 한다. 열기 제거 안내가 계속 반복되면 결함이다.
6. 파괴 칸에 직접 흙/돌을 놓으면 수리 완료로 바뀌지 않아야 한다. 차열벽·지붕·닫힌 문 등 인정 구조로 복구하면 해당 칸 수가 줄어야 한다. 실제 장독 보관 조건을 충족하면 3번째 줄이 별도로 바뀌어야 한다.
7. 파괴 칸이 남은 상태와 재냉각 이후 상태를 각각 저장·이어하기한다. 파괴 칸 목록은 유지되어야 하고 로드만으로 열기 제거 성공 안내가 새로 발생하면 안 된다. 필요하면 저장 JSON의 invasionBrokenCells/invasionLastBaseAttackDay를 개발 측에서 확인한다.
8. 안내·체크패널·예시 윤곽·화살표의 겹침/잘림을 확인한다. 고우선순위 위험 안내 중에는 복구 체크/건축 표식을 숨길 수 있으며 위험이 끝나면 다시 보여야 한다.

## 조준 즉시 갱신 보완

사용자 플레이에서 위험 칸에서 안전 칸으로 옮길 때 이전 경고가 새 칸에 잠깐 표시되는 결함을 확인했다. 채굴 조준 이벤트에서 셀과 위험 판정을 함께 즉시 갱신하며, HUD는 타이머와 분리해 같은 프레임의 경고 상태를 읽는다. 화면 안내 문구도 주기적 안내 갱신과 분리했다.

벽/문 변경(Seal Revision), 코어, SealSystem 인스턴스 변경도 HUD의 프레임 검사에서 즉시 재판정한다. 같은 조준/Revision/코어/SealSystem이면 이전 판정을 재사용하여 Flood Fill을 반복하지 않는다. 거점 유지·복구 상태와 일반 안내 갱신은 기존 0.2초 주기를 유지한다.

CPU 검사에 타이머 없는 조준 변경, 안전 칸으로 이전 경고 전이 방지, 빠른 왕복, 동일 상태에서 타일 읽기/탐색 재실행 없음, 동일 조준 중 벽 변화 즉시 재평가를 포함했다. 총 30/30 통과. 실제 플레이 화면 확인은 하지 않았다.

## 화살표 원본 색상 복원

v86은 ui_raid_arrow 재사용만 명시하며 거점용 녹색은 요구하지 않는다. 개발 중 임의로 넣은 녹색 틴트가 빨간 원본과 곱해져 갈색으로 변색되는 문제를 수정했다. Image.color를 흰색으로 설정하여 납품 원본 색상을 유지한다. 별도 녹색 아트는 요구하지 않는다.

## 목표 화살표 방향 계산 보완

무쇠 발톱 목표(g10)의 대상은 실제 설치된 화로(station:furnace)를 조회한다. 목표 화살표는 Viewport의 정규화된 방향을 Canvas 크기에 직접 적용하여 가로·세로 비율이 다른 화면에서 방향과 가장자리 위치가 왜곡됐다. 거점 화살표와 동일하게 World→Screen→Canvas 로컬 좌표로 변환한 방향을 사용하도록 수정했다. 화면 뒤쪽 대상의 방향 반전도 적용했다. 목표별 대상 조회와 기존 가장자리 여백은 유지한다.

CPU C# 런타임/에디터 프로젝트 컴파일은 오류 0개. Unity/게임 실행으로 화면 검증하지 않았다. 플레이 확인 시 화로·코어가 가까이 있는 상태에서 좌우·상하로 이동하여 두 화살표가 각각의 실제 대상 방향을 가리키는지 확인한다.
