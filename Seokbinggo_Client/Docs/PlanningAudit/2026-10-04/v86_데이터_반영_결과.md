# v86 데이터 반영 결과

확인일: 2026-10-04. 작업 브랜치: `feat/taeyo-ingame-interaction-polish`.
원본: `냥빙고_30일완성_v86_20261003.zip`. 기존 아트·다른 작업물은 보존했다. 커밋·푸시하지 않았다.

## 사용자 지정 예외

| 대상 | 반영 방법 | 확인 |
|---|---|---|
| 느타리·표고·석이 | 원본의 빈 `max_stack`/`mvp_scope`를 기존 `99/A`로 유지 | CSV와 Unity ItemDefinition 모두 99/A |
| 장비 CSV 3개 열 | `verb_id`, `usage_limit_per_day`, `activation_condition`을 기존 프로젝트에서 ID별 보존 | 44행×3열 원본 백업 대조 일치; Unity EquipmentDefinition과 CSV 불일치 0 |
| 아트 | 10/4까지 연결한 최신 아트 보존 | 아이템 카탈로그 172항목·미제공 16개 유지; 버섯 3종 Sprite 연결 확인 |

장비 3개 열은 기획자 답변 전까지 프로젝트 값이 기준이다. 빈 값이나 기본값으로 초기화하지 않는다.

## 변경 내용

- CSV 29개를 v86과 대조해 변경 파일만 반영했다. 위 사용자 지정 예외를 제외한 모든 행·열이 제공본과 일치한다.
- 신규 목표 15개와 안내 문구 36개의 ScriptableObject 모델·임포터·카탈로그 조회를 추가했다. 중복 ID, 목표 순서, 힌트 메시지·아이콘 참조를 검증한다. 새벽 손실 원인 조각 3개는 독립 종료 조건이 없어 빈 `clear_when`을 보존한다.
- 실제 Unity Editor에서 대상별 데이터 재임포트 후 카탈로그를 재구축했다. 제품 데이터 최신성 manifest는 에셋 갱신과 검증 성공 후 기록했다. 관련 없는 에셋 삭제를 포함한 전체 초기화는 실행하지 않았다.
- 생성 카탈로그는 아이템 170개, 제작법 98개, 전역값 262개, 장비 44개, 전투 프로필 19개, 목표 15개, 문구 36개다. 아이템에는 부적 합성 정의 5개, 제작법에는 확장 2개와 부적 합성 5개가 포함된다.
- 기존 임포터가 인식하지 못했던 `table`/`enum`/`tiles` 전역값 단위와 설풍선 전투 프로필 허용 목록을 보완했다. 원본 수치는 바꾸지 않았다.

## 적용된 데이터 차이와 남은 정책 충돌

- 대장간 제작법이 추가됐다: 얼음 모루에서 돌 30·흙 20·철 주괴 8·얼음강철 주괴 6, 90초. CSV는 A 범위지만 문서는 30일 이후 보류로 서술한다. 이번에는 데이터만 반영했으며 별도 노출 정책을 임의로 추가하지 않았다.
- v86 drops.csv에 없는 기존 `ssireum_knot`/`iron_appetite`/`yeouiju_shard` 추가 보스 드롭은 최신 표에 맞춰 재임포트했다. 기존 아트 연결은 제거하지 않았다.
- 앞선 사용자 요청은 B 레시피를 시작부터 공개하는 것이고 v86 문서는 30일 데모에서 숨기도록 한다. 이번 단계에서는 기존 화면 노출 로직을 변경하지 않았다. 후속 범위 정책 작업에서 이 충돌을 명시해야 한다.

## 검증

| 검증 | 결과 |
|---|---|
| CSV 29개 vs v86 원본 전 행·열 대조 | 지정 예외 이외 차이 없음 |
| 병합 데이터에 동봉 verify.py CPU 실행 | 종료 코드 0, 통과 |
| 목표·문구 CSV vs 실제 Unity 생성 에셋 모든 필드 대조 | 불일치 0 |
| Unity 데이터 연결·ID·수량·최신성 검증 | 통과, runtime CSV 28개 manifest 일치 |
| 런타임 C# 프로젝트 CPU 컴파일 | 오류 0, 기존 경고 3 |
| 에디터 C# 프로젝트 CPU 컴파일(런타임 이후 순차) | 오류 0, 기존 경고 38 |
| Unity/게임 실행·플레이 모드·GPU 검증 | 수행하지 않음; 런타임 미검증 |

데이터 최신성 검증은 저장·이어하기나 게임 플레이 검증을 의미하지 않는다. 기존 세이브는 삭제·초기화하지 않았다.

## 후속 단계 / 담당 경계

이번 완료 범위는 데이터 기반 반영이다. 목표 완료 판정·목표 HUD·진행 저장은 아직 연결하지 않았으므로 S1 기능 완료로 볼 수 없다.

> 2026-10-05 후속: [S1 목표 추적 연결·정적 검토](../2026-10-05/v86_S1_목표추적_정적검토.md)를 진행했다. 방향 화살표 원본 미확인과 런타임 미검증은 남아 있다.

1. S1: A의 실제 설치·보관·밀폐·휴식·보스 상태를 목표 완료 판정으로 연결하고, B 담당 HUD와 진행 저장에 전달할 계약을 구현한다.
2. S2~S5: 건축 도우미, 보관·새벽 결과, 안내 우선순위, 결과 성취를 각각 별도 단계로 진행한다.
3. 이무기 얼음 호수 위치·냉기 장치 효과·범위 정책은 전역값을 추가한 것만으로 작동하지 않는다. 해당 서비스 연결을 별도로 구현·검토한다.
4. 기획자 답변을 받으면 장비 3개 열을 ID별 재대조한다. 전체 CSV 덮어쓰기로 초기화하지 않는다.

현재는 데이터·임포터 영역을 변경했다. B 소유 UI/Audio/Save 코드는 이번 단계에서 수정하지 않았다. 이후 S1의 HUD·저장 연결 시 파일 충돌과 저장 호환성을 다시 확인한다.
