# 개발 B 인수인계 명세서 (2026-08-18 · v79)

## 1. 인계 결론

개발 A+C의 확정 범위는 구현 및 검증이 끝났다. 개발 B는 아래 런타임 UI 4건과 그에 딸린 회귀·디버그 계약만 정리한다.

1. D-카운터 제거
2. 31일 자동 데모 종료 제거
3. 이무기 격파 이벤트 기반 결과 화면 연결
4. 결과 화면을 닫으면 게임플레이로 복귀

난이도 옵션은 이미 `난이도 · 준비 중` 비활성 자리로 구현되어 있으므로 유지하고 실제 난이도 로직은 만들지 않는다.

`seokbinggo_s1`~`seokbinggo_s6`는 인벤토리 아이템이 아니라 석빙고 단계 모듈이다. `modules.csv`와 카탈로그 `Modules`만 사용하며 `items.csv` 또는 카탈로그 `Items`에 다시 추가하지 않는다.

> **v79 재확인:** 침공 일정은 `invasion_period_days=10`·`invasion_offset_days=6` 한 벌뿐이다. 구 `wave_night_period`·`wave_night_offset`은 삭제됐고, `wave_mult_target=hp_only`는 31~100일 변종 HP 배율용이라 이번 B UI 작업과 무관하다.

| `survival_continues_after_ending` | `1` | 결과 화면을 닫으면 현재 세션으로 돌아간다. |

## 3. A가 제공하는 런타임 계약

진입점은 `MainGameRuntimeServices.FrostSpread`이다.

```csharp
public event Action<string> EndingReached;
public bool DemoEndingReached { get; }
public bool FinalEndingReached { get; }
public bool SurvivalContinuesAfterEnding { get; }
```

- `EndingReached(bossId)`: `win_gate_demo` 또는 `win_gate_final` 보스를 최초 격파할 때 각각 1회 발생한다.
- B는 문자열 `"imugi_boss"`를 하드코딩하지 않고 이벤트의 `bossId`를 카탈로그의 `win_gate_demo` 값과 비교한다.
- `win_gate_final` 이벤트에는 이번 데모 결과 화면을 표시하지 않는다.
- 동일 보스를 다시 격파해도 이벤트가 중복 발생하지 않는다.
- 처치 상태는 기존 `SaveGame.frostClearedBossIds`로 저장·복원된다.
- 로드 시에는 `DemoEndingReached`가 복원되지만 `EndingReached`를 재발행하지 않는다. 따라서 이어하기 직후 결과 화면이 자동으로 다시 열리지 않는다.
- B는 새 엔딩 저장 필드나 별도 PlayerPrefs를 추가하지 않는다.

## 4. B 수정 대상

### 4.1 `Assets/Scripts/Nyangbingo/UI/MainGameHudController.cs`

- 카탈로그의 `day_counter_display`를 읽고 값이 `off`이면 D-카운터 표시·새벽 구독·애니메이션 경로를 비활성화한다.
- `DayNightService.DaysRemaining`을 사용하는 `dayCounterScrollPresenter.ConfigureForRuntime(...DaysRemaining)` 및 `PlayDayChange(...DaysRemaining)` 연결을 제거한다.
- 기존 배치 자리는 v79 지시대로 경과 일수 또는 폭염 단계 배지에 재사용할 수 있지만, 현재 정상인 HUD 배치를 임의로 바꾸지 않는다.
- 화면 어디에도 `D-숫자`가 남지 않아야 한다. `Day N` 같은 경과 일수 표시는 허용된다.

### 4.2 `Assets/Scripts/Nyangbingo/Debug/MapGeneratorTestHarness.cs`

- 231행 새벽 로그와 291행 디버그 표시의 `D-{DaysRemaining}`를 제거한다.
- 이 파일은 공유 디버그 경계이므로 문구만 외과적으로 정리하고 월드 생성·시간 진행 로직은 변경하지 않는다.

### 4.3 `Assets/Scripts/Nyangbingo/UI/GameShellController.cs`

- `DemoResultState.Teaser = "D-70 — 백일폭염까지"`를 제거한다.
- 날짜 기반 `DemoEndDay`/`ShouldEndDemoAtDawn` 계약을 폐기한다.
- `Result` 상태에서만 성공하는 `ContinueFromResult()` 또는 동등한 전용 상태 전이를 만든다.
- 전용 상태 전이는 `Time.timeScale`을 복원하고 `Gameplay`로 전환하며 현재 세션과 재생 중인 음악을 유지해야 한다.
- 결과 화면을 닫을 때 `TitleRequested`를 발생시키지 않는다. 기존 `ResumeGameplay()`은 `Pause` 상태 전용이므로 결과 버튼에 그대로 연결하지 않는다.
- 타이틀 복귀 기능 자체가 필요하면 일시정지 메뉴의 기존 경로를 유지한다.

### 4.4 `Assets/Scripts/Nyangbingo/UI/MainGameShellUiController.cs`

- `MainGameRuntimeServices.FrostSpread.EndingReached`를 구독하고 `OnDestroy`에서 해제한다.
- 이벤트의 `bossId`가 카탈로그 `win_gate_demo` 값과 같을 때만 현재 데모 결과 화면을 연다.
- `win_gate_final` 값과 일치하는 이벤트에는 이번 데모 결과 화면을 열지 않는다.
- 기존 새벽/31일 판정에서 `shell.ShowResult(...)`를 호출하는 경로를 제거한다.
- 결과 화면 버튼 문구와 동작을 `계속 플레이`로 바꾸고 Gameplay 화면으로 복귀시킨다.

- 결과 화면을 여는 시점의 스냅샷은 기존 `MainGameSaveCoordinator.CaptureSnapshot()`을 사용한다.
