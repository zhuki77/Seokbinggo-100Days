## A-16. v26 배경벽·벽지 전용 Tilemap 구현

### 목적

v26의 `wallpaper`는 플레이어가 설치하는 배경벽입니다. 전경 타일이나 밀폐 경계물이 아니며 충돌도 없어야 합니다. 현재 `TileData`는 전경과 배경을 한 칸에 동시에 안정적으로 저장하기 어려우므로, 개발 A가 월드·타일·저장 계층에서 정식 배경 상태를 제공해야 합니다.

### 확정 규칙

1. 전경과 배경을 논리적으로 분리합니다.
   - 전경 Tilemap: 지형·광물·플레이어 설치 블록, 충돌 대상
   - 배경 Tilemap: 자연 배경벽·플레이어 벽지, 비충돌 대상
2. 지하 자연 지형 생성 시 전경과 해당 지층의 자연 배경을 함께 생성합니다.
3. 자연 동굴로 생성된 칸은 전경과 배경을 모두 비웁니다.
4. 채굴 시 전경만 제거하고 기존 배경은 유지합니다.
5. 벽지는 빈 배경 칸에 플레이어가 설치하며 `seals=0`입니다. `SealSystem`의 경계 또는 누출 차단으로 인정하면 안 됩니다.
6. 자연 지하 배경벽은 벽지 도포율 계산에서 이미 덮인 칸으로 계산합니다.
7. 벽지 제거 시 원래 상태를 복원합니다.
   - 원래 자연 배경이 있던 지하 칸: 원래 자연 배경 복원
   - 원래 하늘 또는 자연 동굴이던 칸: 빈 배경 복원
8. 공식 기획 ID는 `t_bg_dirt`, `t_bg_stone`, `t_bg_deep`입니다. 현재 코드의 `bg_dirt`, `bg_stone`, `bg_deep`과 다르므로 다음 중 하나를 명시적으로 선택해야 합니다.
   - 공식 ID로 일괄 마이그레이션하고 기존 저장 ID를 변환
   - 내부 별칭 테이블을 두어 두 ID를 동일한 타일로 해석

저장 파일을 깨뜨리는 단순 문자열 교체는 금지합니다.

### 벽지 효과 계약

- 발동 조건: 이미 밀폐된 동일 구역의 배경 도포율이 정확히 100%
- 효과: 물단지와 얼음 항아리의 남은 지속시간 및 새 연료 지속시간 +25%
- 적용 제외: 얼음 저장고와 빙정 냉각로
- 변경 금지: 냉기원의 온도 상한 25% / 50% / 100%
- 벽지는 밀폐율, `region_cells`, `leak_faces`를 변경하지 않습니다.

개발 A는 동일한 밀폐 구역 결과를 재사용해 배경 도포율을 계산하고, 개발 B가 읽을 수 있는 명시적 계약을 제공합니다. 예시는 다음과 같으며 실제 명칭이 달라도 같은 정보를 제공해야 합니다.

```csharp
public interface IWallpaperCoverageSource
{
    float GetCoveragePercent(Vector3Int sealCoreCell);
    bool IsCoverageComplete(Vector3Int sealCoreCell);
    event Action WallpaperCoverageChanged;
}
```

도포율은 매 프레임 또는 월드 전체 순회로 계산하지 않습니다. 전경·배경 타일 변경, 코어 변경, 월드 로드처럼 결과가 달라지는 시점에만 관련 구역을 무효화하고 재계산합니다.

### 저장 요구사항

- 자연 배경과 플레이어 벽지의 차이를 보존합니다.
- 전경 변경 이력과 배경 변경 이력을 구분합니다.
- 저장/로드 후 벽지 제거 시에도 원래 자연 배경 또는 빈 배경이 정확히 복원되어야 합니다.
- 기존 저장 파일은 배경 변경 이력이 없어도 로드 가능해야 합니다.
- 손상된 배경 변경 이력 로드가 실패하면 현재 월드와 화면을 부분 변경하지 않습니다.

### 완료 조건

- 지형 생성, 자연 동굴, 채굴, 벽지 설치·제거가 전경/배경 규칙과 일치
- 배경 Tilemap에 Collider가 없음
- 벽지가 밀폐 경계로 계산되지 않음
- 99% 도포 시 효과 없음, 100%에서만 효과 계약 제공
- 저장/로드 후 자연 배경·벽지·빈 배경이 동일하게 복원
- 배경 변경 시 관련 셀만 다시 렌더링

## A-17. 전경 Tilemap 충돌과 런타임 시각 갱신 정식 구현

### 현재 임시 상태

개발 B는 횡스크롤 플레이 검증을 위해 `MainGamePlayerController.MoveWithTileCollision`에서 `TileService` 데이터를 직접 읽는 임시 충돌 방식을 구현했습니다. 이는 개발 A의 정식 Tilemap 충돌 작업이 들어오기 전까지만 사용하는 대체 수단입니다.

또한 테스트 중 지표면 타일을 파괴해도 데이터·아이템·충돌은 갱신되지만 화면 타일이 남는 문제가 발견됐습니다. 현재는 렌더러 바인딩 경로를 보완했지만, 정식 책임은 `TileService`와 `TilemapRenderer`가 가져야 합니다.

### 요구사항

1. 전경 Tilemap에 `TilemapCollider2D`를 구성합니다.
2. 400×160 월드에서 콜라이더 조각 수와 갱신 비용을 줄일 수 있도록 `CompositeCollider2D`와 정적 `Rigidbody2D` 조합을 검토·적용합니다.
3. 배경 Tilemap에는 Collider를 붙이지 않습니다.
4. `TryBreakForeground` 성공 프레임에 다음 상태가 함께 일치해야 합니다.
   - `TileData` 전경이 비어 있음
   - 전경 Tilemap의 해당 셀이 비어 있음
   - 해당 셀의 전경 충돌이 제거됨
   - 배경은 규칙에 맞게 유지 또는 표시됨
5. `TryPlaceForeground` 성공 프레임에는 화면 타일과 충돌이 함께 생겨야 합니다.
6. 월드 전체 재렌더 없이 변경 셀과 콜라이더의 필요한 범위만 갱신합니다.
7. 저장/로드 후 전체 렌더와 충돌 상태가 복원된 `TileData`와 일치해야 합니다.

### A/B 통합 경계

- 개발 A는 `MainGamePlayerController`의 임시 충돌 코드를 삭제하거나 수정하지 않습니다.
- 개발 A는 전경 Tilemap/Collider 구성과 준비 상태를 제공하고 변경 파일을 알립니다.
- 개발 B가 통합 시 임시 `MoveWithTileCollision` 경로를 제거하고 Rigidbody2D 기반 이동과 연결합니다.
- `MainGame` 씬 생성기 수정이 필요하면 개발 B 파일을 직접 바꾸지 말고 필요한 컴포넌트·설정 목록 또는 에디터 설정 API를 먼저 전달합니다.

### 회귀 테스트

- 지표면·지하 타일 파괴 후 데이터/화면/충돌 모두 제거
- 빈 칸 설치 후 데이터/화면/충돌 모두 생성
- 배경 타일 설치·제거 시 충돌 변화 없음
- 여러 셀 연속 채굴 시 이전 Collider가 남지 않음
- 저장/로드 후 파괴·설치된 셀의 화면과 충돌이 동일

## A-18. 새 게임 안전 지표면 스폰을 월드 정본으로 제공

### 현재 임시 상태

현재 생성기가 반환하는 시작점이 중앙의 큰 동굴·수직 구멍 또는 지하 시작 공간과 겹칠 수 있어, 개발 B가 `MainGamePlayerController.ApplyGeneratedWorldSpawn`에서 주변 지표면을 다시 탐색하는 임시 보정을 넣었습니다.

### 요구사항

1. `MapGenerator.GenerateDetailed(seed).spawnPoint` 자체가 최종 안전 지표면 스폰이어야 합니다.
2. 스폰 발밑에는 파괴되지 않은 자연 전경 타일이 있어야 합니다.
3. 플레이어 발과 머리 높이의 최소 2칸이 비어 있어야 합니다.
4. 중앙 싱크홀, 열린 동굴 수직 낙하로, 월드 경계, 보호 구조물 내부를 피합니다.
5. 시작 직후 입력하지 않아도 추락하지 않아야 합니다.
6. 같은 seed는 항상 같은 스폰을 반환합니다.
7. 스폰 주변의 온보딩 자원 접근성과 기존 월드 검증 조건을 유지합니다.
8. 기존 `PlaceStartAlcove`가 지하 스폰을 강제한다면 지표면 안전 스폰 규칙에 맞게 교체하거나 역할을 분리합니다.

개발 A는 `MainGamePlayerController`의 임시 지표 탐색 코드를 수정하지 않습니다. 정식 `spawnPoint`가 전달되면 개발 B가 해당 보정을 제거합니다.

### 회귀 테스트

- 고정 seed 목록과 최소 100개 연속 seed에서 안전 조건 충족
- 같은 seed의 스폰 좌표 결정론 유지
- 스폰 직하 1칸 고체, 발·머리 2칸 공기 확인
- 스폰 아래 일정 깊이까지 즉시 연결된 수직 낙하 공간이 아님을 확인
- 저장/로드 시 새 게임에서 확정된 플레이어 시작 위치가 바뀌지 않음

## A-19. 기존 SealSystem·냉기원 명세에 대한 v26 보충

기존 A-11~A-13의 57×25 창, 코어 중심, `seal_target_cells=240`, 냉기원 상한 계약은 계속 유효합니다. 다음 규칙을 추가합니다.

1. 벽지 도포율과 밀폐율은 서로 다른 값입니다.
2. 벽지는 `SealSystem` 경계로 인정하지 않습니다.
3. 벽지 100% 효과는 `SealPercent` 또는 `TemperaturePercent`를 올리지 않습니다.
4. `ICoolingSourceProvider`는 기존 명세대로 활성 냉기원의 최고 온도 상한을 제공해야 합니다.
5. 벽지 도포율은 별도 계약으로 제공하며, 개발 B가 물단지·얼음 항아리의 지속시간에만 적용합니다.
6. 자연 지하 배경은 도포 완료 셀로 계산하지만, 자연 동굴·지상 하늘의 빈 배경은 벽지를 설치해야 완료 셀이 됩니다.
7. 코어가 없거나 구역이 밀폐되지 않았으면 벽지 완료 효과도 비활성입니다.
8. 월드 로드 후 동일한 `SealSystem` 인스턴스 유지 규칙과 함께 코어 위치, 배경 도포 캐시, 이벤트 구독 상태를 복원합니다.

## A-20. 추가 회귀 테스트 및 인수인계 조건

기존 `Nyangbingo > Run Dev A Regression Tests`에 다음 묶음을 추가합니다.

### 배경·벽지

1. 지하 자연 지형은 전경과 자연 배경을 함께 가짐
2. 자연 동굴은 전경과 배경 모두 비어 있음
3. 채굴은 전경만 제거하고 배경 유지
4. 벽지 설치는 비충돌이며 밀폐 경계에 영향을 주지 않음
5. 99% 도포 효과 없음 / 100% 도포 완료
6. 제거 시 지하는 자연 배경, 지상·동굴은 빈 배경 복원
7. 저장/로드 라운드트립 후 같은 결과

### 충돌·렌더링

1. 파괴 직후 타일 스프라이트와 충돌 동시 제거
2. 설치 직후 타일 스프라이트와 충돌 동시 생성
3. 배경 변경은 충돌에 영향 없음
4. 반복 변경 후 유령 충돌 또는 남은 스프라이트 없음

### 스폰

1. 여러 seed에서 지표면 안전 조건 충족
2. 중앙 구멍 또는 지하 공간에 스폰하지 않음
3. 결정론과 온보딩 자원 접근성 유지

### 최종 인수인계

개발 A PR 본문에 다음을 한글로 기록합니다.

- 수정한 월드·타일·저장 파일 목록
- 새로 추가하거나 변경한 공용 인터페이스 전문
- 배경 타일 ID 마이그레이션 또는 별칭 정책
- MainGame에 필요한 Collider 구성값
- 개발 B가 제거해야 할 임시 코드 위치
- 실행한 Dev A 회귀 테스트 수와 성공 로그
- 기존 저장 파일 호환 결과

개발 A 테스트 후 개발 B의 `DevBTest`, MainGame Play, 새 게임/저장/로드, 제품 빌드까지 깨지지 않아야 완료로 인정합니다.
